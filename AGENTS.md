# Notes for coding agents

Digress is a branching chat for learning. Read README.md for what it does. This file covers how the code fits together and the traps.

## Layout

- `web/index.html`: the entire client (HTML, CSS, JS) in one file. No build step. Libraries come from CDNs: marked, DOMPurify, highlight.js, MathJax 3 (async), mermaid (lazy), pdf.js 3.11 (lazy), MiniSearch (lazy).
- `web/prompts.js`: every instruction the page sends the model (`PROMPTS`: system prompt, quick chips, branch/takeaway/flashcard asks, document preamble text). Put new model-facing text there, not inline. Served at `/prompts.js` (network-first in `sw.js`); the tests' `goto_app` routes it too. Tool descriptions stay in `server/doctools.mjs`.
- `web/threads.js`: `ThreadOps`, pure functions on a conversation: `walk` (the messages on a thread's path, which `buildContext` uses), `signature`, `check`, the relabeling operations `split` / `join` / `swap`, `removeNote`, and `merge` (two devices' changes, three-way). Served and cached like `prompts.js`. `tests/test_threads.py` runs `tests/threads_prop.mjs` (Node): thousands of random operations, checking that no message's context changes and the shape stays valid; `tests/test_merge.py` does the same for `merge` with `tests/merge_prop.mjs`.
- `server/server.mjs`: Node ≥18, **no dependencies**. Keep it that way unless there's a strong reason. `server/runs.mjs`: replies as runs that outlive their connection (see Traps).
- `tests/`: Python Playwright. `run_all.py` runs everything; `test_server.py` uses `tests/fakes/` instead of real Claude.
- `docs/`: user docs linked from README.md (`setup.md`, `remote-access.md`, `development.md`). `docs/media/make_media.py` regenerates the README screenshots and GIF; rerun it when the UI changes visibly. `docs/media/film/make_film.py` rebuilds the one-minute film and its poster (slower; rerun for big visible changes).

## Connectors: the one rule

The client never calls the server directly. It goes through `io = {llm, store, index, files, ready}`, set up once at startup by `initConnectors()`: `findServer()` (`GET api/health` returns `{app:'digress'}`) → `serverLlm`, `serverStore`, `serverFiles`. Opened without its server, the page shows a banner (`noServer()`: `noLlm`, `memoryStore`, `noFiles`) and saves nothing.

New features must use `io.*`. To add a model provider, add an entry to `PROVIDERS` in the server (`available`, `why`, `models`, `web`, `chat`; see `chatViaClaudeCode` / `chatViaApi` / `server/chatgpt.mjs`); the client just reads the NDJSON stream. Several providers can be on at once (one Claude provider, plus ChatGPT once signed in): `/api/models` lists all their models and each chat goes to the provider that owns its model (`providerFor`). Connectors that can't do something say so (`supportsEffort`, `supportsWeb`, `supportsImages`) and the UI hides or works around it.

Server contract:
- `GET /api/health` → `{app:'digress', llm, provider, providers, web, why}`
- `GET /api/models` → `{models:[[id,label]], defaultLabel}`
- `POST /api/chat` `{system, messages, model, effort, web}`: each message's `content` is a string or a list of parts `{type:'text',text}` / `{type:'image',mediaType,data}` (base64; user messages only). `server/content.mjs` checks them and converts them for each provider; anything it doesn't understand is refused (400), never dropped. Also `chat` (32 hex, the run id; the page makes it), `tools`, and `save:{conv,msg}` (where the server writes the reply if no page is connected when it ends). Response: NDJSON lines: `{d:"text"}`, `{search:"query"}`, `{sources:[{title,url}]}`, `{tool}` (any order), `{hb:1}` heartbeats (not counted), then `{done, model, truncated}` or `{error}`
- `GET /api/chat/run/:id?from=N`: reattach to a reply, replaying from line N (`{toolDone}` for tool calls already answered); 404 once it's gone. `POST /api/chat/stop {chat}`: Stop. Dropping a connection never stops a reply.
- `/api/store/{convs|index|cards}[/:id]`: GET list / GET / PUT / PATCH / DELETE. Conversations carry `rev`: PUT with `x-base-rev` → `{rev}`, `409 {current}` if it changed since, `410` if it was deleted; `GET ?rev` → `{rev}`. Deleting a conversation also deletes its layouts and any uploaded file nothing references any more (older than 10 minutes; all at startup after a day).
- `GET /api/layout/:conv` → `{devices:{id:{ui,at}}}`; `PUT /api/layout/:conv?device=ID` with the `ui`. A device not seen for 90 days drops out.
- `/api/files`: `POST ?type=` with raw body → `{id}`; `GET`/`DELETE /api/files/:id`
- `POST /api/fetch-doc` `{url, confirm:[codes]}` → the document's bytes (headers `x-doc-kind`, `x-doc-name`, `x-doc-url`), or `409 {warnings:[{code,text}], url}` when the reader must OK it first (`http`, `ip`, `port`). Client side: `io.files.fromLink` (server connector only; the dialog says so elsewhere).

## Data model

`conv = {id, title, created, updated, rev, threads, msgs, order, ui, nextColor, doc?, pinned?, archived?, views?}`; `ui` isn't saved with it (per device, `api/layout`); `views = {vid:{name, cv, cam, at}}` are the saved canvas views; `doc = {kind, name, assetId?, text?, source?}` (`source`: the link it was opened from)
- Titles: the first question in `main` names the conversation unless `titleKept` (typed in the new-from-document dialog, renamed, or taken from the PDF's own title). A PDF conversation without a typed title starts with `autoTitle` (the file name); once pdf.js reads the metadata, `applyPdfTitle` swaps in `info.Title` / `dc:title` if `pdfTitleOk` finds it real and the title is still `autoTitle`, then drops `autoTitle`.
- User messages can carry `images: [{asset|data, type, w, h}]` (pasted screenshots, stored via `io.files`, inline as a data URL where there's no file storage).
- A snip or whole-page branch from a PDF has `anchorRegion: {x,y,w,h}` (fractions of page `anchorPage`; 0,0,1,1 = the whole page) and `regionText` (the PDF's words inside it); its `anchorText` is just a label. The image isn't stored: it's redrawn from the PDF when needed.

- `threads[tid] = {id, parent, anchorMsg, anchorText, anchorRange:{s,e}, anchorPage, title, colorIdx, resolved?, pinned?, hidden?, alt?}`. `main` is the root. `alt`: another version of a question (Redo/Edit when the reply can't be replaced): it starts after `anchorMsg` (or `'START'`, before the parent's first message) and its first message gets no side-question prefix. `hidden`: left out of the tree, canvas and reply chips (with what's under it) unless `ui.showHidden`.
- Assistant replies keep `model` and `effort`, and `docSeen` (`{of, all}` when the whole document went, `{of, tools, pages}` when it started from part of it, `{n, of, pages}` without tools); `reads` is what it read with the document tools. While pending, `live` (steps) and `t0` drive the activity view; they aren't kept (nor `pending`, `ver`, `toolNow`: `LOCAL_MSG`). `run` (saved) is the server run writing it; `runFrom` how much of `content` came before (Continue); `cut` marks one that stopped before finishing (offers Continue).
- `msgs[mid] = {role: user|assistant|note, thread, text, ...}`; assistant replies made with web on also keep `web`, `searches` and `sources`; `order[tid]` lists a thread's message ids. Notes are takeaways carried back from a branch (`fromThread`).
- `ui`: open/collapsed panes, layout, view (`panes` | `canvas` | `tree`), per-pane zoom `pz[tid]` (a factor; the PDF pane re-renders at it, where 1 = fit width), canvas state `ui.cv` (positions, sizes, z order, per-card zoom `cz`, docked cards `dock`), `ui.cvView` (the view last loaded) and `ui.cvOwn` (this device's canvas from before it loaded one).

## Traps

- **Anchors are character offsets that ignore whitespace** (`anchorRange`), counted by `textWalker`, which skips rendered math, mermaid and footnote markers. Don't change what `textWalker` skips without migrating stored anchors. Older anchors fall back to fuzzy text matching using the surrounding prefix and suffix.
- **PDF text layers end with an empty `.endOfContent` div** that moves around while you select (it fills the gaps between words so the selection doesn't jump, especially on touch). It holds no text, so anchors are unaffected; don't style or count text-layer children without allowing for it.
- **The document pane is the pseudo-thread `'doc'`.** Branches from it have `anchorMsg: 'DOC'`. Code that filters `ui.open` / `ui.collapsed` by existing threads must keep `'doc'` (this broke once).
- **Canvas coordinates:** cards have world positions; the camera scale is `cam.k`, and each card has its own zoom (CSS `zoom` via `--cz`). Stored sizes are at 100%. Anything that converts screen ↔ content uses `contentScale(node)` (which is 1 for cards stuck to the screen). Scroll offsets inside a zoomed card must be divided by it.
- **Startup order:** MathJax loads async and may already be cached, so `__mathReady` can fire before a conversation exists. Keep its guards.
- **Themes:** colors are CSS variables only (including code colors `--hk --hs --hn --ht --hy --hm`). Each theme is a `:root[data-theme=x],.thsw[data-theme=x]` block (the second selector paints the menu's swatches) that must set every color variable, since a swatch doesn't inherit from the default. `THEMES` and `applyTheme` are in a `<head>` script so the theme is set before paint; `data-mode=dark|light` is there for anything that needs to know which kind it is (mermaid uses theme `base` with the theme's variables and is re-rendered on a switch). Don't add `prefers-color-scheme` rules or hard-coded UI colors; PDF pages and images keep their white backgrounds on purpose.
- **Messages are a tree; threads are a labeling of it.** What a message saw is fixed by its path (`ThreadOps.walk`). Anything that rearranges threads must go through `ThreadOps` (`split`, `join`, `swap`; they refuse without changing anything when they can't apply) and keep `tests/test_threads.py` passing. Redo/Edit replace in place only when `redoBlock`/`editBlock` find nothing depending on the reply (latest in its thread, no branch from it, no card from it); otherwise `newVersion` makes an `alt` thread, and "Use this version" is `ThreadOps.swap`. `tests/test_redo.py`, `tests/test_versions.py`.
- **Several devices: saving is versioned and merged.** `flush` saves only the content (`contentOf`: no `ui`, no `LOCAL_MSG` fields) and only when it changed (`sync.sent`), from version `sync.rev`; a 409 goes through `mergeRemote` → `ThreadOps.merge(base, mine, theirs)` → `applyContent` (keeps the objects of replies being written here) → saved again. If merge throws `{conflict}`, `keepCopy` saves this page's version as "… (from this device)"; `{later}` (a reply here is mid-way and would need new ids) waits for it to finish. `catchUp` runs when the tab comes back (visibilitychange, focus, online). `ui` goes to `saveLayout` separately. Anything new in a conversation must survive `merge` (add it to `tests/merge_prop.mjs` if it has rules beyond "one side changed it"); per-page state on a message goes in `LOCAL_MSG`. `tests/test_sync_devices.py` drives two browsers against the real server; `tests/test_sync_replies.py` covers replies that outlive their page (another conversation, a reload, a dropped connection, cut off + Continue).
- **Replies are server runs** (`server/runs.mjs`): the provider writes into a run, not the HTTP response; pages attach and detach. Stop is `io.llm.stop(run)` (`stopReply`), never just aborting the fetch; switching conversation only detaches (`s.detached`), and `resumeRuns` reattaches any message saved with `run`. Document tool calls wait for a page while none is attached. `generate` saves `m.run` before asking (`flushNow`), so `saveOrphan` can write the result in. `tests/test_runs.py`.
- **Columns → canvas** (`setView` → `cvArrive`): the card for the pane last clicked, typed in or scrolled (`lastPane`, else the pane most in view) flashes; the camera pans only if its title bar is off screen. Look only: it never folds, unfolds, expands or saves (don't swap in `focusCard`, which does). `tests/test_canvas_arrive.py`.
- **Canvas views** copy on load: `useView` puts a view's `cv` and camera onto this device's canvas; only Update writes back. `tests/test_views.py`.
- **Shortcuts:** ⌘/Ctrl+K search, ⌘/Ctrl+B sidebar (both work while typing).
- **Search index = passages.** `indexEntries` splits every message and document page into ~900-character passages (`passages()`: paragraphs, code fences kept whole, a ~120-character overlap with the passage before, `o` = its length), with nothing cut off; results are one row per message (its best passage), ranked exact phrase first, then more typed words as typed, then BM25. `IDXV` is the index format: bump it when entries change shape, and older indexes are rebuilt by `idxBackfill`. Document pages are rebuilt from the index with `idxPages` when the document isn't loaded. `tests/test_search_passages.py`, `tests/test_search_phrase.py`.
- **Search scope:** `PAL.scope` is `all` | `conv` | `thread` (`PAL.stid`: the pane last used, `lastPane`, or the one whose magnifier `data-act=jsearch` opened it; `'doc'` = document pages). Filtering happens after ranking, in `searchNow`; Tab cycles the chips. `tests/test_search_scope.py`.
- **Search landing and Back:** `openResult` → `showHit` finds the result's passage in the rendered message (`passageAt`, a run of its words that occurs once), then the typed phrase or the closest cluster of searched words in it (`bestSpot`) and paints them with the CSS Highlight API (`CSS.highlights` `digress-hit`): no DOM changes, so anchors are untouched. `markBack` snapshots the view (conversation, open panes, scroll, camera) once per search (and before a pinned branch opens); the `#backChip` (in the top bar, so it never covers a pane's buttons) pops it (`goBack`); opening a conversation yourself (sidebar, New) clears it. `tests/test_search_jump.py`.
- **Pane headers** wrap: in a narrow pane the buttons go on a row under the title (`.ph` flex-wrap), so don't give `.ph-main` a fixed width. Panes are dragged by the `.pgrip` only. Sidebar branch-row buttons are an overlay (`.macts`), not in the row's flow. `tests/test_polish.py`.
- **Wires** that cross other panes are masked faint over them (an SVG `<mask>` per wire with `data-crossing`); keep the mask rects in sync with pane rects if wires change.
- **`plain()`** (Markdown → text) feeds canvas card previews *and* the search index: changing it changes every index entry's signature (they're rewritten as conversations are next saved or backfilled). Inline LaTeX goes through `texText`; display math becomes "[equation]".
- **Math while streaming:** `renderRich` typesets complete `$…$` / `$$…$$` even while a reply streams, through `texSvg` (a cache of typeset formulas, cloned); unclosed ones stay raw until they close.
- **Diagrams that fail** (`showMermaidSrc`) say why, show mermaid's error and the source, and offer "Ask for a fix" (fills the pane's composer; never sends). `tests/test_mermaid_fallback.py`.
- **Tooltips** (`#tipbox`): `title=` becomes `data-tip` on hover. They hide on `pointerdown` as well as `mousedown` (canvas drags `preventDefault` the pointer event, so no `mousedown` comes) and don't show while a button is held. `tests/test_canvas_tip.py`.
- **Top bar:** `fitTop` moves whatever doesn't fit (in `TOP_MOVABLE` order) into the ⋯ menu (`.tmore`), the same elements, not copies. It reruns on resize and on changes inside the bar. New top-bar controls go in `TOP_MOVABLE` and `MENU_ORDER`. `tests/test_topbar.py`.
- **Class names:** generic names clash with top-bar styles (`.sel` did). Prefix new canvas classes.
- **Web access is search only, and only when asked.** `web` is false unless the reader turned the Web toggle on. Claude Code gets `--tools WebSearch` and nothing else (and `--tools ""` when off), plus `--strict-mcp-config --safe-mode --disable-slash-commands` so none of the user's own MCP servers, hooks, CLAUDE.md or skills load. With the document tools, `--safe-mode` can't be used (it also turns off `--mcp-config` servers), so the same isolation is done piece by piece: `--setting-sources ""`, `--settings '{"disableAllHooks":true}'`, `--strict-mcp-config` with only our server, `--disable-slash-commands`, and the env switches `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` / `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` (checked against a real CLI with a trap CLAUDE.md and hook). Keep both sets in step; never add WebFetch, Bash or file tools there: they run on this machine, and the server has no login. The API path uses the server-side `web_search` tool. ChatGPT (`server/chatgpt.mjs`) sends only `[{type:'web_search'}]` (hosted by OpenAI) and the document tools as function tools; it runs no other tool call. In its tool loop it resends the model's output items (reasoning with `encrypted_content`, messages, calls) and the `function_call_output`s, since `store:false` keeps nothing between requests. Its plan route requires `store:false` + `stream:true` and rejects `system` messages and `max_output_tokens`. Keep the request prefix stable (system prompt as the first developer message, history as separate unchanged turns) so OpenAI's prompt cache keeps working. Source URLs are filtered to http(s) on the server and again in the client.
- **Documents from links are fetched by the server, so `server/fetchdoc.mjs` must stay strict:** http(s) only, no credentials, public addresses only (checked inside the DNS lookup and on every redirect, so rebinding can't slip past), an OK from the reader for http / bare IPs / odd ports, and only real PDFs, UTF-8 text, web pages (handed back as `text/plain`, kind `html`, never served as a page) or, with `image:true`, real PNG/JPEG/WebP/GIF.
- **Web articles** (`articleToMarkdown`): parsed with `DOMParser` (inert), Readability keeps the article, Turndown makes Markdown; the doc is an ordinary text doc with `doc.article:true`. Images become `[Image: alt](url "digress-image")`; `articleFigures` turns those links into placeholders *after* rendering, moving the caption's text node and adding only icon buttons, so the text that anchors count is unchanged (don't add text there). Loaded images are kept in `doc.images[url]` as assets. `view_page` on an article returns the pictures in that part, fetching only URLs found in it, never with the reader's OK implied (`quiet`). `tests/test_article.py` covers it. `DOC_FETCH_TEST_ALLOW` exists for the tests' fake site; never set it otherwise.
- **The server only answers its own page.** `requestAllowed()` refuses requests whose Host isn't localhost/loopback/the `HOST` address/`ALLOWED_HOSTS` (default `.ts.net`; leading dot = suffix) (DNS rebinding) or whose Origin is another site (cross-site POSTs). Keep that check first in `route()`.
- **Flashcards are opt-in per conversation** (`conv.cards = {on, done:{tid: last reply id seen}}`). Cards live in their own collection (`io.cards`; `{id, conv, thread, at:{thread,msg}, where, src, front, back, image?, status: inbox|active|suspended, due, fsrs, reviews}`; `at` is the reply (or takeaway note) it was drafted from, which `openCardSource` scrolls to, and `where` labels it) so review spans conversations. Drafting (`queueDraft` → `draftCards`) runs one model call per thread, queued, and only into the inbox; nothing about cards may show or run in a conversation where they're off (`.cardson` on `#stage`). Scheduling is FSRS-4.5 with default weights (`fsrsNext`). `tests/test_cards.py` covers it.
- **Offline review:** `web/sw.js` (served at `/sw.js`; https or localhost only) caches the page network-first, CDN libraries and fonts cache-first, and `GET /api/files/:id` cache-first; it never caches the rest of `/api/`. `io.cards` is `offlineCards(serverStore('cards'))`: a local copy (`localStorage['digress:cards']`) plus an outbox of changes sent in order when the server is back. If the page loads over http(s) but `/api/health` fails, `offlineMode()` runs: cards only. `tests/test_offline.py` covers it with the real server and service worker.
- **Images in context:** `buildContext` emits `{type:'image', ref}` parts; `resolveContext` turns them into bytes right before sending and fails the whole request if one can't be loaded (never send with a piece missing). Connectors without `supportsImages` get a visible note in place of each image. `tests/test_context.py` checks that every message and image on a branch's path reaches each provider intact; keep it passing.
- **Context building:** `buildContext(tid, excludeMid, {tools})` returns `{system, messages, tools, docSeen}`. The system prompt includes the document (`docPreamble`): whole when it's under `DOC_BUDGET` (200k characters), with `[p. N]` labels. Branches get a prefix quoting the anchor (or, for a snip or page, an image of it). Keep the system prompt identical for every question in a conversation (nothing per-question in it), so all its threads share one prompt cache.
- **Document tools** (`server/doctools.mjs`, `runDocTool` in the client): `search`, `read_pages`, `view_page`, defined once on the server and run in the browser (it has the PDF open). The server sends each call down the reply's stream as `{tool:{id,name,input}}`; the page posts the result to `/api/chat/tool` `{chat,id,parts|error}`, where `session.call` is waiting. The agentic loop is per provider: `chatViaApi` and `chatgpt.chat` loop while the model stops on tool calls; Claude Code runs its own loop against a one-reply MCP endpoint (`/api/mcp/<token>`). Every failure goes back to the model as readable error text, never an empty result; `MAX_TOOL_CALLS` (15) per answer, stated up front in every tool description and counted down in results once 3 or fewer are left, and `MAX_TOOL_ROUNDS` requests per answer for every provider (Claude Code: `--max-turns`). For a document over the budget, the model starts from its table of contents (`pdfOutline`) and the first `DOC_FIRST` pages; a branch about a passage carries that page ±1 in its first message (`aroundParts`). Card drafting and takeaways use the same context and tools as the conversation (same system prompt, so they share its cache); `{tools:false}` gives the old page-picking preamble with gap markers, used when a connection has no tools. `tests/test_doc_tools.py` drives every provider through the same scripted session (`tests/fakes/doc-script.mjs`).

## Testing

```sh
npm install && pip install -r tests/requirements.txt && python -m playwright install chromium
python3 tests/run_all.py            # all
python3 tests/run_all.py dock       # by name
python3 tests/run_all.py -j 1       # one at a time
```

Test files run in parallel (half the cores, at most 8), slowest first by the times in `tests/.artifacts/durations.json`. So each file must stand alone: its own browser, a server on `free_port()`, temp data from `tempfile`, and no fixed file names written outside `tests/.artifacts/<its own name>`.

The UI tests open the app with `common.goto_app()`: it serves `web/index.html` at `http://digress.test/`, maps CDN URLs to `node_modules`, and injects `tests/fakes/page-server.js`, a fake of the server's `/api/*` that runs in the page; each test supplies its fake model as `window.fakeLLM`. Many of them print what they observe: read the output (`tests/.artifacts/*.log`) and the screenshots there when changing that area. `test_server.py`, `test_context.py`, `test_runs.py`, `test_sync_devices.py`, `test_sync_replies.py` and `test_views.py` run the real server (with fake Claude Code / Anthropic / OpenAI from `tests/fakes/`), assert, and exit non-zero. Add a test when you fix a bug.
