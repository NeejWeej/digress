# Notes for coding agents

Digress is a branching chat for learning. Read README.md for what it does. This file covers how the code fits together and the traps.

If `AGENTS.local.md` exists, read it too: notes about this particular machine and how it's run here, kept out of git.

## Layout

- `web/index.html`: the entire client (HTML, CSS, JS) in one file. No build step. Libraries: marked, DOMPurify, highlight.js, MathJax 3 (async), mermaid (lazy), pdf.js 3.11 (lazy), MiniSearch (lazy), Readability and Turndown (lazy). Each comes from this server first (`GET /lib/<pkg>@<ver>/<file>`: `server/libs.mjs` serves node_modules' copy of a file listed in `server/libs.json`, only at that exact installed version, else 404) and from a CDN second; `window.LIBS` (CDN URL → `[lib/ path, hash]`) drives both, with the same SRI hash either way: `needLib` (document.write) for the ones the page starts with, `libElsewhere` for MathJax's async tag, `loadScript` for the lazy ones. Some networks reach the server but not a CDN (a phone couldn't reach jsDelivr, so search never loaded). A new library or version: update `LIBS`, `libs.json`, `package.json` and `tests/common.py`'s `CDN`; `tests/test_sri.py` checks the hashes, `tests/test_local_libs.py` both routes. The demo build copies them to `lib/` too.
- `web/prompts.js`: every instruction the page sends the model (`PROMPTS`: system prompt, quick chips, branch/takeaway/flashcard asks, document preamble text). Put new model-facing text there, not inline. Served at `/prompts.js` (network-first in `sw.js`); the tests' `goto_app` routes it too. Tool descriptions stay in `server/doctools.mjs`.
- `web/threads.js`: `ThreadOps`, pure functions on a conversation: `walk` (the messages on a thread's path, which `buildContext` uses), `signature`, `check`, the relabeling operations `split` / `join` / `swap`, `removeNote`, and `merge` (two devices' changes, three-way). Served and cached like `prompts.js`. `tests/test_threads.py` runs `tests/threads_prop.mjs` (Node): thousands of random operations, checking that no message's context changes and the shape stays valid; `tests/test_merge.py` does the same for `merge` with `tests/merge_prop.mjs`.
- `server/server.mjs`: Node ≥18, **no dependencies**. Keep it that way unless there's a strong reason. `server/runs.mjs`: replies as runs that outlive their connection (see Traps).
- `demo/`: the demo site on GitHub Pages (see Traps: The demo).
- `.github/workflows/`: `tests.yml` runs `tests/run_all.py` on every push and pull request, in Chromium and in WebKit side by side (a matrix setting `DIGRESS_BROWSER`); `demo.yml` publishes the demo after Tests passes on main.
- `tests/`: Python Playwright. `run_all.py` runs everything; `test_server.py` uses `tests/fakes/` instead of real Claude.
- `docs/`: user docs linked from README.md (`setup.md`, `remote-access.md`, `development.md`). `docs/media/make_media.py` regenerates the README screenshots and GIF; rerun it when the UI changes visibly. `docs/media/film/make_film.py` rebuilds the one-minute film and its poster (slower; rerun for big visible changes).

## Connectors: the one rule

The client never calls the server directly. It goes through `io = {llm, store, index, files, ready}`, set up once at startup by `initConnectors()`: `findServer()` (`GET api/health` returns `{app:'digress'}`) → `serverLlm`, `serverStore`, `serverFiles`. Opened without its server, the page shows a banner (`noServer()`: `noLlm`, `memoryStore`, `noFiles`) and saves nothing.

New features must use `io.*`. To add a model provider, add an entry to `PROVIDERS` in the server (`available`, `why`, `models`, `web`, `chat`; see `chatViaClaudeCode` / `chatViaApi` / `server/chatgpt.mjs`); the client just reads the NDJSON stream. Several providers can be on at once (one Claude provider, plus ChatGPT once signed in): `/api/models` lists all their models and each chat goes to the provider that owns its model (`providerFor`). Connectors that can't do something say so (`supportsEffort`, `supportsWeb`, `supportsImages`) and the UI hides or works around it.

Server contract:
- `GET /api/health` → `{app:'digress', llm, provider, providers, web, why}`
- `GET /api/models` → `{models:[[id,label]], defaultLabel, default, chosen}`. `GET|PUT /api/prefs` `{defaultModel}`: preferences shared by every device (`data/prefs.json`); "Default" (`auto`) means the chosen model if a connected provider offers it, else `DEFAULT_MODEL`. The ☆ beside the model picker sets it (`io.llm.setDefault`). `tests/test_default_model.py`.
- `POST /api/chat` `{system, messages, model, effort, web}`: each message's `content` is a string or a list of parts `{type:'text',text}` / `{type:'image',mediaType,data}` (base64; user messages only). `server/content.mjs` checks them and converts them for each provider; anything it doesn't understand is refused (400), never dropped. Also `chat` (32 hex, the run id; the page makes it), `tools`, and `save:{conv,msg}` (where the server writes the reply if no page is connected when it ends). Response: NDJSON lines: `{d:"text"}`, `{search:"query"}`, `{sources:[{title,url}]}`, `{tool}` (any order), `{hb:1}` heartbeats (not counted), then `{done, model, truncated, usage?}`, `{error}`, or `{stopped:'stop'|'away'}` when the server stopped it (Stop, or no page attached for `RUN_DETACH_MS`); a stream that ends without one of these is a dropped connection, and the page reconnects
- `GET /api/chat/run/:id?from=N`: reattach to a reply, replaying from line N (`{toolDone}` for tool calls already answered); 404 once it's gone. `POST /api/chat/stop {chat}`: Stop. Dropping a connection never stops a reply.
- `/api/store/{convs|index|cards}[/:id]`: GET list / GET / PUT / PATCH / DELETE. Conversations carry `rev`: PUT with `x-base-rev` → `{rev}`, `409 {current}` if it changed since, `410` if it was deleted; `GET ?rev` → `{rev}`. Deleting a conversation also deletes its layouts, its search index and any uploaded file nothing references any more (older than 10 minutes; all at startup after a day). The page never deletes a document's file itself: another conversation (New conversation from this document) may use the same one.
- `GET /api/layout/:conv` → `{devices:{id:{ui,at}}}`; `PUT /api/layout/:conv?device=ID` with the `ui`. The ID is per window: the device's ID for window 1, `ID+'w'+n` for window n (see Traps). One not seen for 90 days drops out.
- `/api/files`: `POST ?type=` with raw body → `{id}`; `GET`/`DELETE /api/files/:id`
- `GET /api/guide` → `{docs:[{name,file,text}]}`: the files in `GUIDE_DOCS` (README, docs, this file, `docs/future.md` as "not built yet"), read fresh each time, for "Ask about Digress".
- `POST /api/fetch-doc` `{url, confirm:[codes]}` → the document's bytes (headers `x-doc-kind`, `x-doc-name`, `x-doc-url`), or `409 {warnings:[{code,text}], url}` when the reader must OK it first (`http`, `ip`, `port`). Client side: `io.files.fromLink` (server connector only; the dialog says so elsewhere).

## Data model

`conv = {id, title, created, updated, rev, threads, msgs, order, ui, nextColor, doc?, pinned?, archived?, trashed?, views?, llm?}`; `trashed` (ms; 0 or missing when not) puts it in the sidebar's Trash (`trashConv`, `restoreConv`); the server deletes it `TRASH_DAYS` (7) after (`purgeTrash`, at startup and hourly; the demo on load), with its layout, search index and any file nothing else uses; search and startup leave trashed ones out; `dropCards` (asked once, when it's trashed, only if it has cards: `trashConv`'s dialog, `cardsChoice`) holds its cards out of review (`cardHeld`, in `inScope`) and has Delete for good and `purgeTrash` delete them; Restore clears it; `srcNote` tells a card in review that its source is in the trash or gone (`cardSource`; `convInfo`, not search's `convMeta`); `tests/test_trash.py`, `tests/test_trash_cards.py`; `llm = [model, effort]` is the model main keeps (the actual model id, never `auto`; without it, the latest reply's model); a branch keeps its own in `threads[tid].llm`, else uses its parent's (`threadLlm`, up to main). The picker shows and edits the thread you're in (`pickerTid`: `curPane()`, on the canvas the selected card; `markCur` and `applyStack` call `syncPicker`); `applyConvLlm(tid)` sets it, `stickLlm(tid)` saves it on a picker change or (if the thread has none) on its first question, in `generate`. A model not offered here falls back to `closestModel` (same kind by `modelTier`, else family) without overwriting it (`llmMissing`/`llmSub`); card drafts and fixes use `modelFor(tid)`; `tests/test_conv_model.py`, `tests/test_branch_model.py`; the picker you see is `#mPick` and its menu (`fillModelMenu`: Default, then foldable groups by family, `FAMILIES`/`famOf`, the current one's open, like Appearance; in a group the newest of each kind by `modelTier`/`modelVer` shows and earlier versions fold under `.molder` Older, open when the current model is one of them), over the hidden `#mSel`, which stays the source of truth (picking sets it and fires `change`; `syncPick` keeps the button's label; a test can list models with `window.fakeModels`); `tests/test_model_menu.py`; `doc.mark` is the reading mark (`['p', page, y]` in a PDF, `['o', offset]` in text, an array so a merge takes one side's whole); `ui` isn't saved with it (per window, `api/layout`); `views = {vid:{name, cv, cam, at}}` are the saved canvas views; `doc = {kind, name, assetId?, text?, source?}` (`source`: the link it was opened from)
- Titles: the first question in `main` names the conversation (and a branch's first question names it) unless `titleKept` (a branch gets it when renamed). When the thread's first reply ends, `nameAfterReply` asks a fast model (`titleModel`: Haiku or Terra, the family the conversation's replies use; `PROMPTS.title`) for a short title, only if the title is still the question and that question isn't already short and clear (`goodAsTitle`); it checks again before applying, so a rename meanwhile wins. The fake page server and the demo answer title calls with nothing (a test opts in with `window.fakeTitles`); `tests/test_auto_title.py`. Before that: the first question in `main` names the conversation unless `titleKept` (typed in the new-from-document dialog, renamed, or taken from the PDF's own title). A PDF conversation without a typed title starts with `autoTitle` (the file name); once pdf.js reads the metadata, `applyPdfTitle` swaps in `info.Title` / `dc:title` if `pdfTitleOk` finds it real and the title is still `autoTitle`, then drops `autoTitle`.
- User messages can carry `images: [{asset|data, type, w, h}]` (pasted screenshots, stored via `io.files`, inline as a data URL where there's no file storage).
- A snip or whole-page branch from a PDF has `anchorRegion: {x,y,w,h}` (fractions of page `anchorPage`; 0,0,1,1 = the whole page) and `regionText` (the PDF's words inside it); its `anchorText` is just a label. The image isn't stored: it's redrawn from the PDF when needed.

- `threads[tid] = {id, parent, anchorMsg, anchorText, anchorRange:{s,e}, anchorPage, title, colorIdx, resolved?, pinned?, hidden?, alt?}`. `main` is the root. `alt`: another version of a question (Redo/Edit when the reply can't be replaced): it starts after `anchorMsg` (or `'START'`, before the parent's first message) and its first message gets no side-question prefix. `hidden`: left out of the tree, canvas and reply chips (with what's under it) unless `ui.showHidden`.
- Assistant replies keep `model` and `effort`, `usage` (`{ctx, cached, out, rounds, window?}`: the provider's token counts; `ctx` is the last request's whole input, i.e. how full the context was when the reply ended, `window` the model's context window when the provider says it; shown as "52k / 1M context" under the reply, `ctxLabel`), and `docSeen` (`{of, all}` when the whole document went, `{of, tools, pages}` when it started from part of it, `{n, of, pages}` without tools); `reads` is what it read with the document tools. While pending, `live` (steps) and `t0` drive the activity view; they aren't kept (nor `pending`, `ver`, `toolNow`: `LOCAL_MSG`). `run` (saved) is the server run writing it; `runFrom` how much of `content` came before (Continue); `cut` marks one that stopped before finishing (offers Continue).
- `msgs[mid] = {role: user|assistant|note, thread, text, ...}`; assistant replies made with web on also keep `web`, `searches` and `sources`; `order[tid]` lists a thread's message ids. Notes are takeaways carried back from a branch (`fromThread`).
- `ui`: open/collapsed panes (a device with no layout of its own takes the latest other one, its own device's windows first; from another device through `otherScreen`, which drops `sizes`, `pz`, the canvas's `dock`, `pre` and `cz`, sized for that screen), layout (`cols` | `rows`), view (`panes` | `canvas`), per-pane zoom `pz[tid]` (a factor; the PDF pane re-renders at it, where 1 = fit width), canvas state `ui.cv` (positions, sizes, z order, per-card zoom `cz`, docked cards `dock`), `ui.cvView` (the view last loaded) and `ui.cvOwn` (this device's canvas from before it loaded one).

## Traps

- **Anchors are character offsets that ignore whitespace** (`anchorRange`), counted by `textWalker`, which skips rendered math, mermaid and footnote markers. Don't change what `textWalker` skips without migrating stored anchors. Older anchors fall back to fuzzy text matching using the surrounding prefix and suffix.
- **PDF text layers end with an empty `.endOfContent` div** that moves around while you select (it fills the gaps between words so the selection doesn't jump, especially on touch). It holds no text, so anchors are unaffected; don't style or count text-layer children without allowing for it.
- **The document pane can live on the canvas.** When the document's card is docked (`S.dock.doc`, via Expand or snapping it to an edge) and the canvas is showing, the real `paneEls.get('doc')` element is moved into that card (`placeDocPane`, after every `renderCanvas` and `layout`); `layout()` skips it meanwhile (`docInDock`), and switching back to Columns/Rows puts it back. Expand (`docdock`) fills the canvas (`REGIONS.fill`); dragging to a side edge or **Side** (`docside`) docks it to half; a branch marker followed from the filled document moves it to the side first. Clicks inside it go to the pane's own handlers, except branch markers, which go to their cards. Don't clone the pane or render the PDF a second time. Moving the element resets its scroll (a reader on p. 95 landed on p. 1), so where you are is kept as a mark-like spot as you scroll (`noteDocSpot`, `docView.spot`) and put back after each move and after the PDF is laid out again at a new width (`putDocSpot`): one spot shared by both views. `tests/test_canvas_doc.py`, `tests/test_doc_view_spot.py`. A PDF is never laid out at a hidden or moving pane's zero width (`buildPdfPages` sets `docView.stale` instead, and the resize watcher redraws once the pane has a width): it once came out at the 260px minimum and stayed there, docked on the canvas on a slow machine. A text document re-wraps the moment its width changes (a pane closed, the sidebar hidden), so the doc pane's ResizeObserver puts the spot back at once (`pb.__tw`); a PDF does it after it's redrawn. `tests/test_doc_text_reflow.py`. Thread panes do the same (`paneRO`, `notePaneSpot`/`paneSpotNow`/`putPaneSpot`): the exact character at the reading line (`caretAt`/`charRect`; else the message, the block in it and how far into it; or `bottom`), measured from the top of the pane, not of its `.pb` (a narrow pane's header wraps, and unwraps when it widens), unless something jumped the pane elsewhere since its spot was noted (a nudge from the browser's own scroll anchoring still counts as the same place). `tests/test_pane_keep_place.py` (at iPad size, with Chrome's scroll anchoring off, as Safari has none).
- **The document pane is the pseudo-thread `'doc'`.** Branches from it have `anchorMsg: 'DOC'`. Code that filters `ui.open` / `ui.collapsed` by existing threads must keep `'doc'` (this broke once).
- **Canvas coordinates:** cards have world positions; the camera scale is `cam.k`, and each card has its own zoom (CSS `zoom` via `--cz`). Stored sizes are at 100%. Anything that converts screen ↔ content uses `contentScale(node)` (which is 1 for cards stuck to the screen). Scroll offsets inside a zoomed card must be divided by it.
- **Startup order:** MathJax loads async and may already be cached, so `__mathReady` can fire before a conversation exists. Keep its guards.
- **Themes:** colors are CSS variables only (including code colors `--hk --hs --hn --ht --hy --hm`). Each theme is a `:root[data-theme=x],.thsw[data-theme=x]` block (the second selector paints the menu's swatches) that must set every color variable, since a swatch doesn't inherit from the default. `THEMES` and `applyTheme` are in a `<head>` script so the theme is set before paint; `data-mode=dark|light` is there for anything that needs to know which kind it is (mermaid uses theme `base` with the theme's variables and is re-rendered on a switch). Don't add `prefers-color-scheme` rules or hard-coded UI colors; PDF pages and images keep their white backgrounds on purpose. The exception is the reader's choice of **PDF pages** look (`PDF_LOOKS`, `applyPdfLook` in the `<head>` script, `settings.pdf`, `data-pdf` on the root): a CSS `filter` on `.dpage canvas` only (Dark is invert + hue-rotate; `match` is Dark under `data-mode=dark`), so the text layer, markers and reading mark are untouched and snips/page images for the model are drawn unfiltered. `tests/test_pdf_look.py` (which also checks every theme sets every color variable). The palette menu (**Appearance**, `#themeB`) groups `THEMES` by mode into foldable sections (`themeGroup`, `.thgrp` + `.thlist`, with PDF pages as a third), and two rows below them: **Lines between panes** (`setWires`, `settings.wires`, `.nowires` on `#app`; on unless turned off; the canvas's own lines aren't affected; `tests/test_wires_toggle.py`) and **Fit to this screen** (`fitScreen`: clears `ui.sizes`, `ui.pz` and the canvas's `cz`; `tests/test_phone_fit.py`); opening it unfolds the section holding the current theme, and `placeThemes` keeps it on screen (it scrolls inside). `tests/test_theme.py`.
- **Messages are a tree; threads are a labeling of it.** What a message saw is fixed by its path (`ThreadOps.walk`). Anything that rearranges threads must go through `ThreadOps` (`split`, `join`, `swap`; they refuse without changing anything when they can't apply) and keep `tests/test_threads.py` passing. Redo/Edit replace in place only when `redoBlock`/`editBlock` find nothing depending on the reply (latest in its thread, no branch from it, no card from it); otherwise `newVersion` makes an `alt` thread, and "Use this version" is `ThreadOps.swap`. Retry (an errored reply) and Continue (a cut one) change a reply in place too, so they follow the same rule (`retryBlock`): Retry asks as another version and Continue isn't offered (this mixed conversations up once). Anything new that rewrites a reply must check it too. **Start over** (`startMainOver`, document conversations) is `ThreadOps.split` of main before its first message: main empties and its messages become an `alt` version from `START`; Undo is `ThreadOps.join`. **New conversation from this document** (`newFromDoc`) copies `doc` (not `mark`) and shares its `assetId`. `tests/test_redo.py`, `tests/test_versions.py`, `tests/test_start_over.py`.
- **Several devices: saving is versioned and merged.** `flush` saves only the content (`contentOf`: no `ui`, no `LOCAL_MSG` fields) and only when it changed (`sync.sent`), from version `sync.rev`; a 409 goes through `mergeRemote` → `ThreadOps.merge(base, mine, theirs)` → `applyContent` (keeps the objects of replies being written here) → saved again. If merge throws `{conflict}`, `keepCopy` saves this page's version as "… (from this device)"; `{later}` (a reply here is mid-way and would need new ids) waits for it to finish. `catchUp` runs when the tab comes back (visibilitychange, focus, online). `ui` goes to `saveLayout` separately. A save that fails (a dropped connection) keeps `dirty` and retries (`retrySave`: 2 s, doubling to 30 s; `saveSoon` at once on `online`, the tab shown or hidden, `pagehide`); while `saveFailed`, leaving the conversation asks (`leaveOk`, before `openConv`, New, from a document) and `beforeunload` warns. `tests/test_save_retry.py` (the fake server's `window.fakeOffline`). Anything new in a conversation must survive `merge` (add it to `tests/merge_prop.mjs` if it has rules beyond "one side changed it"); per-page state on a message goes in `LOCAL_MSG`. `tests/test_sync_devices.py` drives two browsers against the real server; `tests/test_sync_replies.py` covers replies that outlive their page (another conversation, a reload, a dropped connection, cut off + Continue).
- **Several windows on one machine** share the device ID (`DEVICE`, localStorage). Each window also takes a number (`WINDOW`: the lowest Web Lock `digress:window:n` no other window holds, kept in sessionStorage so a reload keeps it) and saves its layout under `layoutKey()`, so a canvas in one window and columns in another don't overwrite each other. Every save, rename or delete of a conversation is announced on the `BroadcastChannel('digress')` (`toldWindows` wraps `io.store`); the window showing it runs `catchUp(true)` (a window on another monitor stays visible and never gets focus, so it wouldn't otherwise). The address names the open conversation, `#c=ID` (`showInUrl`, replaceState, only once saved; startup reads it in `maybeOpenLatest` before writing it); ⌘/Ctrl- or middle-click in the sidebar opens a conversation in a new window. The tab is named by window and view (`tabName`: "Digress 2 · Canvas"), never by the conversation's title, which would end up in browser history. `tests/test_windows.py`.
- **Replies are server runs** (`server/runs.mjs`): the provider writes into a run, not the HTTP response; pages attach and detach. Stop is `io.llm.stop(run)` (`stopReply`), never just aborting the fetch; switching conversation only detaches (`s.detached`), and `resumeRuns` reattaches any message saved with `run`. Document tool calls wait for a page while none is attached. `generate` saves `m.run` before asking (`flushNow`), so `saveOrphan` can write the result in. `tests/test_runs.py`.
- **Columns → canvas** (`setView` → `cvArrive`): the card for the pane last clicked, typed in or scrolled (`lastPane`, else the pane most in view) flashes; the camera pans only if its title bar is off screen. Look only: it never folds, unfolds, expands or saves (don't swap in `focusCard`, which does). `tests/test_canvas_arrive.py`. The card then stays marked (`cvHere`, `.here`, `#cvHereTag`) for the whole canvas visit (cleared by switching to Columns/Rows or another conversation); while it's marked, `#zHere` in the canvas toolbar glides back to it (`panToCard`).
- **Canvas drags own their press** (`cvTake`): panning, moving or resizing a card turns text selection off for the whole page until the press ends (`.cvnosel`) and sets `cvTook`, so `checkSelection` opens no branch popup from text the drag swept over (the docked document, a card). A card brought into view (`panToCard`, `focusCard`, `cvArrive`) is centred in `cvFree()`, the part of the canvas not covered by docked cards. In the docked document, the pane-only buttons (reorder grip, Collapse, Collapse others) are hidden. `tests/test_canvas_doc.py`.
- **Where a takeaway ends** (`takeawayCut`): a takeaway note records `upTo`, the last message of its branch it saw (older ones are worked out from the messages' `ts`). Once the branch goes on past it, a divider (`.tkcut`, `takeawayCuts`, `tkcutEl`) sits after that message in the pane and the canvas card; it goes to the note (`goToTakeaway`), and the branch's name in the note's header goes to the cutoff (`goToTakeawaySource`). The divider sits between messages, never inside one, so anchors are unaffected. `tests/test_takeaway_cut.py`.
- **Jumping to where a branch came from, on the canvas** (`canvasRevealSource`, from the branch card's `.cq` line; a whole-reply branch's line says "The whole reply"): a docked document is the real pane, so it uses `revealDocAnchor` and the pane's own Return. A thread card (main or any branch) remembers where it was being read in `cvPrev` (per conversation and card, outside the element, since `renderCanvas` rebuilds cards) and shows Return (`.cjp` in its `.cjump`, `.hasprev`). `tests/test_canvas_return.py`.
- **Branch chips** (`branchChips`): under each reply, a chip per branch off it (`shownOn`), in a pane (`buildFoot`) and in an open canvas card (`canvasMsgEl`), outside `.body` so anchors are unaffected. It's the only way into a branch about the whole reply, which has no inline marker; on the canvas a chip goes to the branch's card (`focusCard`) and its line starts there (`drawEdges`). `tests/test_canvas_whole_branch.py`.
- **Canvas views** copy on load: `useView` puts a view's `cv` and camera onto this device's canvas; only Update writes back. `tests/test_views.py`.
- **Shortcuts** (see also the panel, below): ⌘/Ctrl+K search, ⌘/Ctrl+B sidebar, ⌘/Ctrl+. Zen, ⌘/Ctrl+' canvas ⇄ panes, ⌘/Ctrl+Shift+' Columns ⇄ Rows, ⌘/Ctrl+\ collapse/expand and ⌘/Ctrl+Shift+\ close the pane you're in (`curPane`: `lastPane`, strips included, else `focusedPane`; outlined `.cur` by `markCur` with 2+ panes; `keyClose` has Undo; on the canvas ⌘\ clicks the selected card's expand) (all work while typing). They're listed in `KEYS` (the shortcuts panel) and in README.md: keep both in step when adding one (`tests/test_keys_panel.py` checks the README). `tests/test_view_keys.py`, `tests/test_pane_keys.py`.
- **Search index = passages.** `indexEntries` splits every message and document page into ~900-character passages (`passages()`: paragraphs, code fences kept whole, a ~120-character overlap with the passage before, `o` = its length), with nothing cut off; results are one row per message (its best passage), ranked exact phrase first, then more typed words as typed, then BM25. `IDXV` is the index format: bump it when entries change shape, and older indexes are rebuilt by `idxBackfill`. Document pages are rebuilt from the index with `idxPages` when the document isn't loaded. `tests/test_search_passages.py`, `tests/test_search_phrase.py`.
- **Search scope:** `PAL.scope` is `all` | `conv` | `thread` (`PAL.stid`: the pane last used, `lastPane`, or the one whose magnifier `data-act=jsearch` opened it; `'doc'` = document pages). Filtering happens after ranking, in `searchNow`; Tab cycles the chips. `tests/test_search_scope.py`.
- **"Describe it instead"** (`findExpand`, `findPick`; prompts in `PROMPTS.find`): one-off model calls with a fast model (`fastModel`), never added to a conversation or saved. Step 1 sends only the typed description and the titles in the search's scope (`scopeTitles`), never message text; its phrases are searched as usual and merged, and each result keeps the phrase that found it (`r.q`, used for its preview and landing). Step 2 runs only when chosen and sends ~300-character snippets of the top 25 candidates. Hidden offline or without a model. `tests/test_search_describe.py`.
- **Search landing and Back:** `openResult` → `showHit` finds the result's passage in the rendered message (`passageAt`, a run of its words that occurs once), then the typed phrase or the closest cluster of searched words in it (`bestSpot`) and paints them with the CSS Highlight API (`CSS.highlights` `digress-hit`): no DOM changes, so anchors are untouched. `markBack` snapshots the view (conversation, open panes, scroll, camera) once per search (and before a pinned branch opens); the `#backChip` (in the top bar, so it never covers a pane's buttons) pops it (`goBack`); opening a conversation yourself (sidebar, New) clears it. `tests/test_search_jump.py`.

## Testing

```sh
npm install && pip install -r tests/requirements.txt && python -m playwright install chromium
python3 tests/run_all.py            # all
python3 tests/run_all.py dock       # by name
python3 tests/run_all.py -j 1       # one at a time
```

Test files run in parallel (half the cores, at most 8), slowest first by the times in `tests/.artifacts/durations.json`. So each file must stand alone: its own browser, a server on `free_port()`, temp data from `tempfile`, and no fixed file names written outside `tests/.artifacts/<its own name>`.

The UI tests open the app with `common.goto_app()`: it serves `web/index.html` at `http://digress.test/`, maps CDN URLs to `node_modules`, and injects `tests/fakes/page-server.js`, a fake of the server's `/api/*` that runs in the page; each test supplies its fake model as `window.fakeLLM`. Most tests check what they observe and exit non-zero on a failure; many also print observations and save screenshots in `tests/.artifacts/`, so read those when changing that area. Tests that import `start` from `test_server.py` (directly or via `sync_common.py`) run the real server with fake Claude Code / Anthropic / OpenAI from `tests/fakes/`. Add a test when you fix a bug.

**Safari (WebKit).** `DIGRESS_BROWSER=webkit` runs every test in WebKit instead (`common.py` swaps `p.chromium` for it); a test that needs a Chromium-only tool (CDP touch input, `page.pdf`) calls `chromium_only(why)` and passes as skipped. WebKit differs in ways that have bitten: no scroll anchoring (content that re-wraps or changes above you moves you; see the pane spots above); a hidden or moved element's scroll resets to the top (`setView` keeps each pane's `__viewTop` across the canvas, `keepPaneTops` across a catch-up's redraw; both through `holdScroll`, which keeps putting it back for up to a second while the pane is still laying out, since the first try can be clamped short, and stops when the reader scrolls, touches, clicks or types; the document pane has its own spot and is left out); `scrollLeft`/`scrollTop` round to whole pixels (`+=` a fraction each frame falls behind: keep the exact value, as the edge-grow does); a press while text is selected elsewhere can start a native drag of that text and swallow the pointer events (resize handles `preventDefault` and clear the selection); private browsing can't store a Blob in IndexedDB (the demo keeps files as bytes); `page.route` also sees `blob:` URLs (let them through). A request cut off by a reload or navigation is reported as a page error even though the page handles it: before `pg.reload()`, wait for `quiet(pg)` (no request in flight; `BOOT_WATCH` counts them). A test written in Chrome can pass for the wrong reason: check it at an iPad size too.
