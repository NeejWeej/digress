# Documents: anchors, PDFs, text, articles, the reading mark

Part of the notes for coding agents; [AGENTS.md](../AGENTS.md) has the overview and the index.

- **Anchors are character offsets that ignore whitespace** (`anchorRange`), counted by `textWalker`, which skips rendered math, mermaid and footnote markers. Don't change what `textWalker` skips without migrating stored anchors. Older anchors fall back to fuzzy text matching using the surrounding prefix and suffix.
- **PDF text layers end with an empty `.endOfContent` div** that moves around while you select (it fills the gaps between words so the selection doesn't jump, especially on touch). It holds no text, so anchors are unaffected; don't style or count text-layer children without allowing for it.
- **A passage across a page break** (`crossPageText`): the browser's range follows the text layer's order, which isn't the reading order (a sidebar box or a footer can come after the paragraph you selected). So it keeps pieces by position: on the first page from the start on down until the first piece that's above the start line or in the top/bottom `PAGE_EDGE` (7%) of the page, so the highlight stays one run; middle pages without header/footer; on the last page from its first such piece (`anchorEnd.s`) to the end. The selection's own first and last lines are always kept, even in the margin. Lines are joined with a space: pdf.js ends a line with a `<br>`, which `Range.toString()` leaves out ("Oneof"). `tests/test_pdf_cross_page.py` (a generated PDF with a header, a box after the body in the content stream, and a footer).
- **The document pane is the pseudo-thread `'doc'`.** Branches from it have `anchorMsg: 'DOC'`. Code that filters `ui.open` / `ui.collapsed` by existing threads must keep `'doc'` (this broke once).
- **Reading mark** (`conv.doc.mark`; `placeMark`, `readingSpot`, `markButton`, `dragMark`, `offerMark`): the ribbon button in the document pane's jump stack marks where the view's top 15% line is (`READ_LINE`); with a mark it opens a menu (go back, move here, remove). The ribbon and line (`.dmark`) are drawn inside the page (PDF, as a percentage) or the `.docbody` (text, from the character offset, redrawn when it reflows), in the margin, never in the text, so anchors are unaffected. Reopening the conversation offers "Go back to it" when the mark is out of view. `tests/test_reading_mark.py`.
- **Web articles** (`articleToMarkdown`): parsed with `DOMParser` (inert), Readability keeps the article, Turndown makes Markdown; the doc is an ordinary text doc with `doc.article:true`. Images become `[Image: alt](url "digress-image")`; `articleFigures` turns those links into placeholders *after* rendering, moving the caption's text node and adding only icon buttons, so the text that anchors count is unchanged (don't add text there). Loaded images are kept in `doc.images[url]` as assets. Math (KaTeX, MathJax, Wikipedia, MathML with a TeX annotation or `alttext`) becomes `$…$` / `$$…$$` (`articleTex`, the `math` rule; Readability strips classes, so the ones it needs are kept with `classesToPreserve: MATH_CLASSES`); without it a formula's text came through as its characters run together plus the escaped TeX, and a table became one word wider than the screen. `view_page` on an article returns the pictures in that part, fetching only URLs found in it, never with the reader's OK implied (`quiet`). `tests/test_article.py` covers it. `DOC_FETCH_TEST_ALLOW` exists for the tests' fake site; never set it otherwise.
- **Page citations** (`linkPages`, `a.pref`): `[p. 4]`, `[p. 20–22]` and lists (`[p. 2, 7]`, `[pp. 5, 13–15]`, `[p. 3; p. 9]`) in a reply become links that show the page; in a list each page or range is its own link (the first takes the `[p. `, the last the `]`), and the text stays exactly as written, so anchors in the reply don't move. Not inside code or links. `tests/test_page_links.py`.
