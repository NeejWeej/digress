# Layout: what each file and folder is

Part of the notes for coding agents; [AGENTS.md](../AGENTS.md) has the overview and the index.

- `web/index.html` + `web/styles.css` + `web/js/`: the client (HTML shell and pre-paint theme/font/lib boot in `index.html`, stylesheet in `styles.css`, native ES modules in `web/js/`: `app.js` coordinator/boot/sync/popover/topbar, `state.js` shared runtime state + thread helpers + cross-module `app` action registry, pure modules `fsrs.js`, `text.js`, `anchors.js`, `context.js`, `share.js`, `connectors.js`, `searchrank.js` (search ranking, imported by `server/db.mjs` too; `tests/test_search_parity.py`), and UI subsystems `render.js`, `cards.js`, `media.js`, `doc.js`, `panes.js`, `canvas.js`, `generation.js`, `search.js`, `sidebar.js`, `modals.js`). No build step. Served at `/js/<name>.js` (network-first in `sw.js`, copied recursively by `demo/build.mjs`, routed by `tests/common.py`'s `goto_app`). Pure modules are unit-tested directly in Node (`tests/test_client_modules.py` → `tests/client_modules_unit.mjs`, `tests/test_context_unit.py` → `tests/context_unit.mjs`, `tests/test_server_unit.py` → `tests/server_unit.mjs`), and `npm run lint` runs ESLint (`no-undef`, `no-dupe-keys`, `no-unused-vars`) over `web/js/`, `server/`, and `demo/build.mjs`. Libraries: marked, DOMPurify, highlight.js, MathJax 3 (lazy, loaded on first math), mermaid (lazy), pdf.js 4.10 (lazy ES module; uses a real module Web Worker via `/lib/` or SRI-verified blob fallback on CDN), MiniSearch (lazy), Readability and Turndown (lazy), html-to-image (lazy, for snips of text documents). Each comes from this server first (`GET /lib/<pkg>@<ver>/<file>`: `server/libs.mjs` serves node_modules' copy of a file listed in `server/libs.json`, only at that exact installed version, else 404) and from a CDN second; `window.LIBS` (CDN URL → `[lib/ path, hash]`) drives both, with the same SRI hash either way: `needLib` (document.write) for the ones the page starts with, `loadScript` for the lazy ones. Some networks reach the server but not a CDN (a phone couldn't reach jsDelivr, so search never loaded). Fonts come the same way (see ui.md, Themes). A new library or version: update `LIBS`, `libs.json`, `package.json` and `tests/common.py`'s `CDN` (fonts need no `CDN` entry: `cdn_font`); `tests/test_sri.py` checks the hashes, `tests/test_local_libs.py` both routes. The demo build copies them to `lib/` too.
- `web/prompts.js`: every instruction the page sends the model (`PROMPTS`: system prompt, quick chips, branch/takeaway/flashcard asks, document preamble text). Put new model-facing text there, not inline. Served at `/prompts.js` (network-first in `sw.js`); the tests' `goto_app` routes it too. Tool descriptions stay in `server/doctools.mjs`.
- **The app registry** (`app` in `web/js/state.js`): the UI modules (`panes`, `canvas`, `doc`, `sidebar`, `search`, `cards`, `generation`, `modals`) are built by factories (`createPanes()`…) whose functions live in closures, so they reach each other through `app`, filled in one place: `Object.assign(app, {...})` near the end of `app.js` (each module opens with delegate stubs, `const x = (...a) => app.x(...a)`). A name used through `app` is invisible to lint, so `tests/test_app_registry.py` (→ `tests/app_registry.mjs`) checks every `app.X` used is registered; a new cross-module call must be added to that block. `node tests/app_registry.mjs --map` prints which module uses which names from whom (the dependency map). **Redraws go through `web/js/redraw.js` instead**: the owner registers `onRedraw('panes', layout)` (keys: `panes`, `wires`, `wires-soon` in panes.js; `map`, `conv-list`, `title` in sidebar.js; `canvas`, `edges-soon` in canvas.js; `badges` in generation.js) and other modules call `invalidate('panes')`; the same test checks every key has exactly one handler. `invalidate` redraws at once (see ui.md, "Redraws").
- `web/threads.js`: `ThreadOps`, pure functions on a conversation: `walk` (the messages on a thread's path, which `buildContext` uses), `signature`, `check`, the relabeling operations `split` / `join` / `swap`, `removeNote`, and `merge` (two devices' changes, three-way). Served and cached like `prompts.js`. `tests/test_threads.py` runs `tests/threads_prop.mjs` (Node): thousands of random operations, checking that no message's context changes and the shape stays valid; `tests/test_merge.py` does the same for `merge` with `tests/merge_prop.mjs`.
- `server/server.mjs`: Node ≥22.5 (uses built-in `node:sqlite`), **no runtime npm dependencies**. Keep it that way unless there's a strong reason. `server/runs.mjs`: replies as runs that outlive their connection (see server.md, Replies are server runs).
- `demo/`: the demo site on Cloudflare Workers, with GitHub Pages only redirecting old links (see demo.md).
- `.github/workflows/`: `tests.yml` runs `tests/run_all.py` on every push and pull request, in Chromium and in WebKit side by side (a matrix setting `DIGRESS_BROWSER`, each split into 4 shards with `--shard`, inside the prebuilt Playwright container so there's no apt or browser download step), after `npm run lint`; `demo.yml` publishes the demo after Tests passes on main's latest commit (never an older one over a newer), and when that run doesn't pass, reruns its failed jobs once, so one stalled runner can't leave the demo behind main until the next push.
- `tests/`: Python Playwright. `run_all.py` runs everything; `test_server.py` and the tests that import its `start` use `tests/fakes/` (Claude Code, Anthropic, OpenAI; Gemini in `test_gemini.py`, `test_context.py`, `test_doc_tools.py`) instead of real models.
- `evals/`: `prompt_eval.mjs` compares two versions of `web/prompts.js` (a git ref vs the working copy) on the questions in `cases.mjs`, against a real model through a running server, and writes them side by side to `evals/out/` (ignored by git). It costs real usage, so nothing runs it automatically: not `run_all.py`, not CI. Run it by hand after changing the system prompt or `howDigress`, and add a case when a prompt change targets a behaviour none of them covers.
- `docs/`: user docs linked from README.md (`guide.md`, `setup.md`, `flashcards.md`, `clipper.md`, `remote-access.md`, `development.md`, and the roadmap `future.md` / `done.md`). `docs/media/make_media.py` regenerates the README screenshots and GIF; rerun it when the UI changes visibly. `docs/media/film/make_film.py` rebuilds the one-minute film and its poster (slower; rerun for big visible changes).
