# Layout: what each file and folder is

Part of the notes for coding agents; [AGENTS.md](../AGENTS.md) has the overview and the index.

- `web/index.html` + `web/styles.css` + `web/js/`: the client (HTML shell and pre-paint theme/font/lib boot in `index.html`, stylesheet in `styles.css`, native ES modules in `web/js/`: `app.js` entry point plus pure modules `fsrs.js`, `text.js`, `anchors.js`, `context.js`, `share.js`). No build step. Served at `/js/<name>.js` (network-first in `sw.js`, copied recursively by `demo/build.mjs`, routed by `tests/common.py`'s `goto_app`). Pure modules are unit-tested directly in Node (`tests/test_client_modules.py` → `tests/client_modules_unit.mjs`, `tests/test_context_unit.py` → `tests/context_unit.mjs`). Libraries: marked, DOMPurify, highlight.js, MathJax 3 (lazy, loaded on first math), mermaid (lazy), pdf.js 3.11 (lazy; uses a real Web Worker when served from `/lib/`, fake worker on CDN fallback), MiniSearch (lazy), Readability and Turndown (lazy), html-to-image (lazy, for snips of text documents). Each comes from this server first (`GET /lib/<pkg>@<ver>/<file>`: `server/libs.mjs` serves node_modules' copy of a file listed in `server/libs.json`, only at that exact installed version, else 404) and from a CDN second; `window.LIBS` (CDN URL → `[lib/ path, hash]`) drives both, with the same SRI hash either way: `needLib` (document.write) for the ones the page starts with, `loadScript` for the lazy ones. Some networks reach the server but not a CDN (a phone couldn't reach jsDelivr, so search never loaded). Fonts come the same way (see ui.md, Themes). A new library or version: update `LIBS`, `libs.json`, `package.json` and `tests/common.py`'s `CDN` (fonts need no `CDN` entry: `cdn_font`); `tests/test_sri.py` checks the hashes, `tests/test_local_libs.py` both routes. The demo build copies them to `lib/` too.
- `web/prompts.js`: every instruction the page sends the model (`PROMPTS`: system prompt, quick chips, branch/takeaway/flashcard asks, document preamble text). Put new model-facing text there, not inline. Served at `/prompts.js` (network-first in `sw.js`); the tests' `goto_app` routes it too. Tool descriptions stay in `server/doctools.mjs`.
- `web/threads.js`: `ThreadOps`, pure functions on a conversation: `walk` (the messages on a thread's path, which `buildContext` uses), `signature`, `check`, the relabeling operations `split` / `join` / `swap`, `removeNote`, and `merge` (two devices' changes, three-way). Served and cached like `prompts.js`. `tests/test_threads.py` runs `tests/threads_prop.mjs` (Node): thousands of random operations, checking that no message's context changes and the shape stays valid; `tests/test_merge.py` does the same for `merge` with `tests/merge_prop.mjs`.
- `server/server.mjs`: Node ≥22.5 (uses built-in `node:sqlite`), **no runtime npm dependencies**. Keep it that way unless there's a strong reason. `server/runs.mjs`: replies as runs that outlive their connection (see server.md, Replies are server runs).
- `demo/`: the demo site on GitHub Pages (see demo.md).
- `.github/workflows/`: `tests.yml` runs `tests/run_all.py` on every push and pull request, in Chromium and in WebKit side by side (a matrix setting `DIGRESS_BROWSER`); `demo.yml` publishes the demo after Tests passes on main's latest commit (never an older one over a newer), and when that run doesn't pass, reruns its failed jobs once, so one stalled runner can't leave the demo behind main until the next push. The install step has apt timeouts for the same reason.
- `tests/`: Python Playwright. `run_all.py` runs everything; `test_server.py` uses `tests/fakes/` instead of real Claude.
- `evals/`: `prompt_eval.mjs` compares two versions of `web/prompts.js` (a git ref vs the working copy) on the questions in `cases.mjs`, against a real model through a running server, and writes them side by side to `evals/out/` (ignored by git). It costs real usage, so nothing runs it automatically: not `run_all.py`, not CI. Run it by hand after changing the system prompt or `howDigress`, and add a case when a prompt change targets a behaviour none of them covers.
- `docs/`: user docs linked from README.md (`guide.md`, `setup.md`, `flashcards.md`, `remote-access.md`, `development.md`). `docs/media/make_media.py` regenerates the README screenshots and GIF; rerun it when the UI changes visibly. `docs/media/film/make_film.py` rebuilds the one-minute film and its poster (slower; rerun for big visible changes).
