# Flashcards and offline review

Part of the notes for coding agents; [AGENTS.md](../AGENTS.md) has the overview and the index.

- **Flashcards are opt-in per conversation** (`conv.cards = {on, done:{tid: last reply id seen}}`). Cards live in their own collection (`io.cards`; `{id, conv, thread, at:{thread,msg}, where, src, front, back, image?, status: inbox|active|suspended, due, fsrs, reviews}`; `at` is the reply (or takeaway note) it was drafted from, which `openCardSource` scrolls to, and `where` labels it) so review spans conversations. Drafting (`queueDraft` → `draftCards`) runs one model call per thread, queued, and only into the inbox (`draftingT` per branch drives `markCardButtons`: the branch's Cards button drafts only what's new since `done[tid]` (`since`), else opens that branch's cards, `KS.thread`; **Draft more** forces one). A card's `quote` (`{text,msg}` or `{text,page}`) is the model's verbatim source sentence, kept only if `findQuote` finds it (words in order, any punctuation or markup between); shown only with the answer, and `openCardSource` lands on it with `showQuote` (the search highlight). Review scope `KS.scope` is `'all'` or a conversation id (`cardsPicker`). `tests/test_cards_quote.py`. **Fix…** in review (`fixForm` → `sendFix` → `runFix` → `askFix`, `PROMPTS.cardFix`) sets `c.fix = {state: pending|ready|failed, note, tags, verdict, why, change, cards}`: a card with `fix` is out of review (`dueCards`) and in the inbox (`inInbox`, `fixItem`) until Accept (`acceptFix`: `change:'answer'` resets `fsrs`) or Keep original drops it; a card from a conversation that isn't open goes with its stored branch as text. **Edit** (`KS.editing`) works on the review face too. `tests/test_cards_fix.py`. nothing about cards may show or run in a conversation where they're off (`.cardson` on `#stage`). **Draft automatically** (`conv.cards.auto`, missing = true; the `.kauto` checkbox in the panel's footer, `data-kauto`): `cardsAuto(conv)` in context.js (on and `auto !== false`) gates everything that drafts by itself: `cardsAfterReply` (a highlight's first reply, a takeaway), and `suggest_card` being offered (`cardToolOf`, and `resumeRuns`'s tool list). Manual drafting (`makeCardsFor`, Make cards, Draft more) only needs `cardsOn()`. Turning it off changes the tools offered, so the next reply's prompt cache is cold. It merges field by field like `on` (`merge3`). `tests/test_cards_manual.py`. Scheduling is FSRS-4.5 with default weights (`fsrsNext`). `tests/test_cards.py` covers it.
- **Offline review:** `web/sw.js` (served at `/sw.js`; https or localhost only) caches the page network-first, CDN libraries and fonts cache-first (the font stylesheet, offline and never saved, is answered empty: system fonts, not an error), and `GET /api/files/:id` cache-first; it never caches the rest of `/api/`. `io.cards` is `offlineCards(serverStore('cards','',{timeout:8000}))`: a local copy (`localStorage['digress:cards']`) plus an outbox of changes sent in order when the server is back. Nothing waits on the network: `put`/`remove` write locally and flush in the background (retried on `online`, tab shown, and every 30 s while stuck; `stuck` + `onchange` → `cardsSyncChanged`: one toast, and the review's `.kpend` count); `list` falls back to the local copy after 2.5 s. Skip (`skipCard`, `KS.skipped`, `reviewQueue`) puts a card at the back for the session. `tests/test_cards_offline_review.py`. If the page loads over http(s) but `/api/health` fails, `offlineMode()` runs: cards only. `tests/test_offline.py` covers it with the real server and service worker.
