# Testing

Part of the notes for coding agents; [AGENTS.md](../AGENTS.md) has the overview and the index.

```sh
npm install && pip install -r tests/requirements.txt && python -m playwright install chromium
python3 tests/run_all.py            # all
python3 tests/run_all.py dock       # by name
python3 tests/run_all.py -j 1       # one at a time
```

Test files run in parallel (half the cores, at most 8), slowest first by the times in `tests/.artifacts/durations.json`. So each file must stand alone: its own browser, a server on `free_port()`, temp data from `tempfile`, and no fixed file names written outside `tests/.artifacts/<its own name>`.

The UI tests open the app with `common.goto_app()`: it serves `web/index.html` at `http://digress.test/`, maps CDN URLs to `node_modules`, and injects `tests/fakes/page-server.js`, a fake of the server's `/api/*` that runs in the page; each test supplies its fake model as `window.fakeLLM`. Most tests check what they observe and exit non-zero on a failure; many also print observations and save screenshots in `tests/.artifacts/`, so read those when changing that area. Tests that import `start` from `test_server.py` (directly or via `sync_common.py`) run the real server with fake Claude Code / Anthropic / OpenAI from `tests/fakes/`. Add a test when you fix a bug. Don't wait a fixed time for something to happen: CI's WebKit machine is slow, and a glide or a redraw that takes 300 ms here can take a second there. Wait for the state itself (`soon`, `wait_for_function`), or after an action use `settle(pg, ms)` (the old wait, then until nothing moves); a fixed `wait_for_timeout` is only for checking that something does *not* happen, or where elapsed time is the point (a hold, a drag, a tooltip's delay), marked `# deliberate`. Before a reload, `quiet(pg)`.

**Safari (WebKit).** `DIGRESS_BROWSER=webkit` runs every test in WebKit instead (`common.py` swaps `p.chromium` for it); a test that needs a Chromium-only tool (CDP touch input, `page.pdf`) calls `chromium_only(why)` and passes as skipped. WebKit differs in ways that have bitten: no scroll anchoring (content that re-wraps or changes above you moves you; see the pane spots in canvas.md, "The document pane can live on the canvas"); a hidden or moved element's scroll resets to the top (`setView` keeps each pane's `__viewTop` across the canvas, `keepPaneTops` across a catch-up's redraw; both through `holdScroll`, which keeps putting it back for up to a second while the pane is still laying out, since the first try can be clamped short, and stops when the reader scrolls, touches, clicks or types; the document pane has its own spot and is left out); `scrollLeft`/`scrollTop` round to whole pixels (`+=` a fraction each frame falls behind: keep the exact value, as the edge-grow does); a press while text is selected elsewhere can start a native drag of that text and swallow the pointer events (resize handles `preventDefault` and clear the selection); private browsing can't store a Blob in IndexedDB (the demo keeps files as bytes); `page.route` also sees `blob:` URLs (let them through). A request cut off by a reload or navigation is reported as a page error even though the page handles it: before `pg.reload()`, wait for `quiet(pg)` (no request in flight; `BOOT_WATCH` counts them). A test written in Chrome can pass for the wrong reason: check it at an iPad size too.
