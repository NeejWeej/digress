# The demo site

Part of the notes for coding agents; [AGENTS.md](../AGENTS.md) has the overview and the index.

- **The demo** (`demo/`; its note in the corner can be dragged out of the way, kept per tab; files are stored as bytes, since Safari's private browsing can't keep a Blob in IndexedDB; published at neejweej.github.io/digress): `demo/build.mjs` copies `web/` and adds only two `<script>` tags at the top of `<head>`: `demo/replies.js` and `demo/demo.js`, an in-browser stand-in for the server that answers `api/*` (IndexedDB for conversations, cards, layouts and files; relative to the page, since it's served under `/digress/`). So the demo is always the current page, and anything that changes the server contract must change `demo/demo.js` too. It has its own service worker, `demo/sw.js`, in place of the app's: it keeps nothing offline and only revalidates every request (`cache: 'no-cache'`), since GitHub Pages sends `max-age=600` and a visit after a deploy otherwise opened the old page for ten minutes (`tests/test_sw_fresh.py`, Chromium only: Playwright's WebKit doesn't send a navigation with a fresh cached copy through the service worker at all, so whether Safari gets the new page at once is unchecked). Replies (`DemoReplies.reply(body)`) are written in advance for the sample reading (`PREPARED`, keyed by the question; its `[p. N]` must match `demo/sample.pdf`), and otherwise quote the document's closest passages and say it's the demo; never make a fallback look like a model's answer. The sample conversation (`demo/seed.json`) is made by `demo/make_sample.py`, which prints `demo/sample/bayes.html` to PDF and clicks through the built demo; rerun it when the reading or the prepared replies change. "Ask about Digress" reads `demo/guide.json`, built from `guideDocs()` (`server/guide.mjs`). `tests/test_demo.py` builds the site and drives it.
