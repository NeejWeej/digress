# The server: contract, runs, providers, safety

Part of the notes for coding agents; [AGENTS.md](../AGENTS.md) has the overview and the index.

The client never calls the server directly. It goes through `io = {llm, store, index, files, ready}`, set up once at startup by `initConnectors()`: `findServer()` (`GET api/health` returns `{app:'digress'}`) → `serverLlm`, `serverStore`, `serverFiles`. Opened without its server, the page shows a banner (`noServer()`: `noLlm`, `memoryStore`, `noFiles`) and saves nothing.

New features must use `io.*`. To add a model provider, add an entry to `PROVIDERS` in the server (`available`, `why`, `models`, `web`, `chat`; see `chatViaClaudeCode` / `chatViaApi` / `server/chatgpt.mjs`); the client just reads the NDJSON stream. Several providers can be on at once (one Claude provider, plus ChatGPT once signed in, plus Gemini with a key: `server/gemini.mjs`, the same shape as `chatgpt.mjs`; function calls go back with their `thoughtSignature`, as Gemini requires; an overloaded Google sometimes refuses at once (503, tried again twice: `GEMINI_RETRY_MS`) and sometimes never answers (given up after `GEMINI_WAIT_MS`, 90 s, with a plain message); Google sometimes sends no `groundingChunks` for a reply that searched and still links its results through Google's redirect, so with Web on and no sources sent, `groundedLinks` takes the sources from those `vertexaisearch.cloud.google.com/grounding-api-redirect/` links, named by their link text (logged under `DEV`)): `/api/models` lists all their models and each chat goes to the provider that owns its model (`providerFor`). Connectors that can't do something say so (`supportsEffort`, `supportsWeb`, `supportsImages`) and the UI hides or works around it.

Server contract:
- `GET /api/health` → `{app:'digress', llm, provider, providers, web, why}`
- `GET /api/models` → `{models:[[id,label]], defaultLabel, default, chosen}`. `GET|PUT /api/prefs` `{defaultModel}`: preferences shared by every device (`data/prefs.json`); "Default" (`auto`) means the chosen model if a connected provider offers it, else `DEFAULT_MODEL`. The ☆ beside the model picker sets it (`io.llm.setDefault`). `tests/test_default_model.py`.
- `POST /api/chat` `{system, messages, model, effort, web, tools?}`: `tools` names the page's tools this reply offers (`['search','read_pages','view_page','suggest_card']`, any of them; `true` means the three document tools; `pickTools`): each message's `content` is a string or a list of parts `{type:'text',text}` / `{type:'image',mediaType,data}` (base64; user messages only). `server/content.mjs` checks them and converts them for each provider; anything it doesn't understand is refused (400), never dropped. Also `chat` (32 hex, the run id; the page makes it), `tools`, and `save:{conv,msg}` (where the server writes the reply if no page is connected when it ends). Response: NDJSON lines: `{d:"text"}`, `{search:"query"}`, `{sources:[{title,url}]}`, `{tool}` (any order), `{hb:1}` heartbeats (not counted), then `{done, model, truncated, usage?}`, `{error}`, or `{stopped:'stop'|'away'}` when the server stopped it (Stop, or no page attached for `RUN_DETACH_MS`); a stream that ends without one of these is a dropped connection, and the page reconnects
- `GET /api/chat/run/:id?from=N`: reattach to a reply, replaying from line N (`{toolDone}` for tool calls already answered); 404 once it's gone. `POST /api/chat/stop {chat}`: Stop. Dropping a connection never stops a reply.
- `/api/store/{convs|index|cards|skills|prompts}[/:id]`: GET list / GET / PUT / PATCH / DELETE. `GET /api/store/convs?meta=1` returns cached metadata (`_meta: true`, without `msgs`/`threads`) for the sidebar list (`io.store.listMeta`, validated by file `mtimeMs`+`size`; also supported by `demo/demo.js` and `tests/fakes/page-server.js`). Static files and large JSON responses support `Accept-Encoding: gzip` and weak `ETag`/`304`. `skills`: SKILL.md files added in the app; `prompts`: one doc, `custom` (see model-context.md, Prompts, skills & tools). Conversations carry `rev`: PUT with `x-base-rev` → `{rev}`, `409 {current}` if it changed since, `410` if it was deleted; `GET ?rev` → `{rev}`. Deleting a conversation also deletes its layouts, its search index and any uploaded file nothing references any more (older than 10 minutes; all at startup after a day). The page never deletes a document's file itself: another conversation (New conversation from this document) may use the same one.
- `GET /api/layout/:conv` → `{devices:{id:{ui,at}}}`; `PUT /api/layout/:conv?device=ID` with the `ui`. The ID is per window: the device's ID for window 1, `ID+'w'+n` for window n (see data-model.md, Several windows). One not seen for 90 days drops out.
- `/api/files`: `POST ?type=` with raw body → `{id}`; `GET`/`DELETE /api/files/:id`
- `GET /api/connections` → `{providers:[{id, name, kind: cli|key|login, on, from?: env|app, last4?, note?}]}`; `PUT /api/connections/:id {key}` (anthropic, gemini: checked with the provider first, kept in `data/keys.json` at 0600, `.env` wins, 409 if set there) and `DELETE` → the same list. A key never goes back to the page. Providers, the Claude side and `enabled()` are worked out per request (`primary`, `claudeSide`, `candidates`, `apiKey`), so a key added in the app works without a restart; the page re-reads health and models (`io.llm.refresh`). The Connections panel (`openConnections`, from the model menu's `.mconn`). Tests keep real keys out: `start()` sets `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` and `GOOGLE_API_KEY` empty so the server's `.env` can't fill them. `tests/test_gemini.py` (server, `tests/fakes/fake-gemini.mjs`), `tests/test_connections.py` (page).
- `GET /api/tools` → `{tools:[{name,description,schema}], maxCalls, maxCards}`: every tool the page can offer, as the model sees it (the Prompts page's Tools section; the demo builds `demo/tools.json`).
- `GET /api/guide` → `{docs:[{name,file,text}]}`: the files `guideDocs()` lists (README, docs, AGENTS.md and every file in `agents/`, `docs/future.md` as "not built yet"), the list and the files read fresh each time, for "Ask about Digress".
- `POST /api/fetch-doc` `{url, confirm:[codes]}` → the document's bytes (headers `x-doc-kind`, `x-doc-name`, `x-doc-url`), or `409 {warnings:[{code,text}], url}` when the reader must OK it first (`http`, `ip`, `port`). Client side: `io.files.fromLink` (server connector only; the dialog says so elsewhere).
- **Replies are server runs** (`server/runs.mjs`): the provider writes into a run, not the HTTP response; pages attach and detach. Stop is `io.llm.stop(run)` (`stopReply`), never just aborting the fetch; reattaching treats a 5xx without JSON as the server restarting (keep trying) but one with `{error}` as the server's own answer (a busy model) and shows it; switching conversation only detaches (`s.detached`), and `resumeRuns` reattaches any message saved with `run`. Document tool calls wait for a page while none is attached. `generate` saves `m.run` before asking (`flushNow`), so `saveOrphan` can write the result in. `tests/test_runs.py`.
- **Token counts** come from the providers, never estimated: `useRound` (server.mjs) reads each request's usage from `message_start`/`message_delta` (the API and Claude Code's stream events alike), ChatGPT's from `response.completed`, Gemini's from `usageMetadata`. A reply with tool rounds is several requests that each resend everything, so `ctx` is the last one's, not a sum. For Anthropic/Claude, `useRound` also records `cacheTtl` (300 s default, or 3600 s when `cache_creation.ephemeral_1h_input_tokens > 0`) and `cacheAt` (UTC epoch ms) whenever tokens were read from or written to cache; ChatGPT and Gemini have no fixed published TTL, so they omit `cacheTtl`. The window: Claude Code's `result.modelUsage[model].contextWindow`, the Anthropic Models API's `max_input_tokens`, ChatGPT's model list `context_window`, Gemini's `inputTokenLimit`. `tests/test_server.py`.
- **Web access is search only, and only when asked.** `web` is false unless the reader turned the Web toggle on. Claude Code gets `--tools WebSearch` and nothing else, always (when `WEB_SEARCH` allows web at all), and `--allowedTools WebSearch` only when Web is on: listed but not allowed, a call is refused (`-p` asks no one), and the tool list, which comes first in the prompt, stays the same, so switching Web keeps the prompt cache (checked against the real CLI: `--disallowedTools` removes the tool from the list, so don't use it). Plus `--strict-mcp-config --safe-mode --disable-slash-commands` so none of the user's own MCP servers, hooks, CLAUDE.md or skills load. With the document tools, `--safe-mode` can't be used (it also turns off `--mcp-config` servers), so the same isolation is done piece by piece: `--setting-sources ""`, `--settings '{"disableAllHooks":true}'`, `--strict-mcp-config` with only our server, `--disable-slash-commands`, and the env switches `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` / `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` (checked against a real CLI with a trap CLAUDE.md and hook). Keep both sets in step; never add WebFetch, Bash or file tools there: they run on this machine, and the server has no login. The API path uses the server-side `web_search` tool. ChatGPT (`server/chatgpt.mjs`) sends only `[{type:'web_search'}]` (hosted by OpenAI) and the document tools as function tools; it runs no other tool call. `web_search` is listed whether Web is on or not (`payload.webListed`), and `tool_choice` (`allowed_tools`, or `none`) says what may run, so the tools stay the same (OpenAI's keep-prefix-unchanged guidance). The API path still adds and removes `web_search` (docs/future.md). The model learns it may search from `PROMPTS.webOn` on the question (and the system prompt's rule); `buildContext` adds it to every question whose reply had Web on (`webFor`), never from the current setting, except for the question being answered. Same for `PROMPTS.lookingAt`: the page is saved on the question (`m.lookAt`, set in `send`). Anything else added to a message must also come from what's saved with it, so earlier messages read the same in every request; `tests/test_prefix_stable.py`. In its tool loop it resends the model's output items (reasoning with `encrypted_content`, messages, calls) and the `function_call_output`s, since `store:false` keeps nothing between requests. Its plan route requires `store:false` + `stream:true` and rejects `system` messages and `max_output_tokens`. Keep the request prefix stable (system prompt as the first developer message, history as separate unchanged turns) so OpenAI's prompt cache keeps working. Source URLs are filtered to http(s) on the server and again in the client.
- **Documents from links are fetched by the server, so `server/fetchdoc.mjs` must stay strict:** http(s) only, no credentials, public addresses only (checked inside the DNS lookup and on every redirect, so rebinding can't slip past), an OK from the reader for http / bare IPs / odd ports, and only real PDFs, UTF-8 text, web pages (handed back as `text/plain`, kind `html`, never served as a page) or, with `image:true`, real PNG/JPEG/WebP/GIF.
- **The server only answers its own page.** `requestAllowed()` refuses requests whose Host isn't localhost/loopback/the `HOST` address/`ALLOWED_HOSTS` (default `.ts.net`; leading dot = suffix) (DNS rebinding) or whose Origin is another site (cross-site POSTs). Keep that check first in `route()`.
