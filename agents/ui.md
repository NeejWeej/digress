# Panes, chrome, themes, keys and the rest of the page

Part of the notes for coding agents; [AGENTS.md](../AGENTS.md) has the overview and the index.

- **Startup order:** MathJax loads async and may already be cached, so `__mathReady` can fire before a conversation exists. Keep its guards.
- **Themes:** colors are CSS variables only (including code colors `--hk --hs --hn --ht --hy --hm`). Each theme is a `:root[data-theme=x],.thsw[data-theme=x]` block (the second selector paints the menu's swatches) that must set every color variable, since a swatch doesn't inherit from the default. `THEMES` and `applyTheme` are in a `<head>` script so the theme is set before paint; `data-mode=dark|light` is there for anything that needs to know which kind it is (mermaid uses theme `base` with the theme's variables and is re-rendered on a switch). Don't add `prefers-color-scheme` rules or hard-coded UI colors; PDF pages and images keep their white backgrounds on purpose. The exception is the reader's choice of **PDF pages** look (`PDF_LOOKS`, `applyPdfLook` in the `<head>` script, `settings.pdf`, `data-pdf` on the root): a CSS `filter` on `.dpage canvas` only (Dark is invert + hue-rotate; `match` is Dark under `data-mode=dark`), so the text layer, markers and reading mark are untouched and snips/page images for the model are drawn unfiltered. `tests/test_pdf_look.py` (which also checks every theme sets every color variable). **Fonts** work the same way (`FONTS`, `applyFont` in the `<head>` script, `settings.font`, `data-font` on the root): each sets only `--sans` (the app) and `--serif` (replies), never `--mono`, and a web font's stylesheet is added only when that font is first used. Fonts are `@fontsource` packages served like the libraries (`fontCss`: this server's `lib/` copy, else jsDelivr's, the same SRI hash; never Google Fonts): their stylesheets are in `LIBS` (in the `<head>` script, so `BASE_FONTS`, the three every page uses, load before paint) and `libs.json`, and the server serves the `.woff2` files a listed stylesheet names and no other file of the package (`libPaths`). A font's CSS family is its `@fontsource` name (`'Inter Variable'`). The Appearance menu (`.thapp`) keeps its own font, so previewing a bigger one can't move its rows under the pointer (it swapped back and forth once); hovering anything in it that isn't an option puts back what's chosen (`unpreview`). The palette menu (**Appearance**, `#themeB`) groups `THEMES` by mode into foldable sections (`themeGroup`, `.thgrp` + `.thlist`, with PDF pages and Font after them), and two rows below them: **Lines between panes** (`setWires`, `settings.wires`, `.nowires` on `#app`; on unless turned off; the canvas's own lines aren't affected; `tests/test_wires_toggle.py`) and **Fit to this screen** (`fitScreen`: clears `ui.sizes`, `ui.pz` and the canvas's `cz`; `tests/test_phone_fit.py`); opening it unfolds the section holding the current theme, and `placeThemes` keeps it on screen (it scrolls inside). `tests/test_theme.py`.
- **Shortcuts** (see also the panel, below): ⌘/Ctrl+K search, ⌘/Ctrl+B sidebar, ⌘/Ctrl+. Zen, ⌘/Ctrl+' canvas ⇄ panes, ⌘/Ctrl+Shift+' Columns ⇄ Rows, ⌘/Ctrl+\ collapse/expand and ⌘/Ctrl+Shift+\ close the pane you're in (`curPane`: `lastPane`, strips included, else `focusedPane`; outlined `.cur` by `markCur` with 2+ panes; `keyClose` has Undo; on the canvas ⌘\ clicks the selected card's expand) (all work while typing). They're listed in `KEYS` (the shortcuts panel) and in README.md: keep both in step when adding one (`tests/test_keys_panel.py` checks the README). `tests/test_view_keys.py`, `tests/test_pane_keys.py`.
- **Zen** (`setZen`, `#app.zen`, per window in sessionStorage): hides the top bar and sidebar (the wires between panes stay); ⌘/Ctrl+. (also while typing), the Zen button (moves into ⋯ like other top-bar controls) or the `#zenX` tab at the top leave it. The Back chip lives in the top bar, so it's hidden in Zen. The sidebar can still come out over the panes (`.zenside`: ⌘/Ctrl+B through `#tSide`, or the `#zenS` tab at the left edge); a click outside it or Esc puts it away. `tests/test_zen.py`.
- **Installed as an app** (`web/manifest.webmanifest`, `display: standalone`; icons from `docs/media/make_icons.py`; the server serves them by name, the demo copies them): `installedApp()` is matchMedia's display-mode. Zen doesn't go full screen there (it once did, and Android turns pinch-zoom off in full screen). Android's back is kept inside the app by one extra history entry (`guardBack`, `BACK_GUARD`): `popstate` runs `closeTopmost()` (dialogs, menus, search, the branch list, the popup, flashcards, the guide, the sidebar; never a pane) and, with nothing open, a toast and no guard for `BACK_AGAIN_MS`, so a second back leaves. `popstate` calls `showInUrl()` first, so the entry under the guard can't switch conversations through `hashchange`. Anything new that opens over the page and closes with Escape belongs in `closeTopmost`. `theme-color` follows `--panel` (`applyTheme`). `tests/test_installed_app.py`.
- **Collapse others** (shown so; called `focus` in the code: `toggleFocus`, `isFocused`, `data-act=focus`) collapses every pane but this one; again, or Esc, expands them. Its icon (`focus`) is a wide pane between strips, used for nothing else (the canvas's expand and fill buttons have their own, `expand`, corners out), the same while on (pressed, in the accent colour: a separate "on" icon looked like the Columns view); a PDF's fit-to-width (`zfit`, `fitw`) is ↔ between bars, so the two don't look alike.
- **Pane headers** wrap: in a narrow pane the buttons go on a row under the title (`.ph` flex-wrap, `.ph-act` wraps too), so don't give `.ph-main` a fixed width. No header button is hidden for lack of room (zoom once was, and a phone couldn't reach it). The header line's crumbs and quote are real `<button>`s (`.crumb`, `.oqt`): as styled spans, a phone's tap was moved to the line around them (touch adjustment goes to the nearest clickable element) and did nothing; `tests/test_phone_branch_controls.py`. The takeaway bar (`.tk`) comes after the floating search stack (`.jumpw`) in a pane, so the stack sits above it rather than over its ✕; a swipe closes it too. Panes are dragged by the `.pgrip` only, or a collapsed strip (`.pane.rail`) by itself (a click still expands it). Pinned, Folders, Conversations and Branches fold (a line sets Branches apart: it is only the open conversation's) (`.sfoldw`, `sideFold`, localStorage `sq:fold`); the Conversations list shows every unpinned conversation, filed ones included with a `.ftag` (folders group, they don't hide); inside Folders (`#foldWrap`, always there; `#flist`, then the `#newFolder` row), each folder folds too (`.fgrp`, `toggleFolder`, localStorage `digress:ffold`), its header a `.citem.fhd` so its rename/remove buttons act like a row's; a row's folder button (Move to…) opens `#folderMenu` (`openFolderMenu`, in `closeTopmost`; it keeps the id in `data-cid`, never `data-conv`, which the sidebar's click handler takes for a row): the folders, New folder…, Take out, and Archive (an active row has no archive button of its own; an archived one keeps Move back). New folder is a dialog (`newFolderDialog`: a name and the conversations to put in it, since a folder can't be empty; OK is disabled until both), also from the `#newFolder` row at the end of Folders; `tests/test_folders.py` and `#plist`/`#clist` scroll inside themselves (`listCur` brings the open one's row into view), so Branches and How it works stay near; `tests/test_side_fold.py`. Sidebar branch-row buttons are an overlay (`.macts`), not in the row's flow. `tests/test_polish.py`.
- **Resize handles** (`.gut`, `gutEl`/`gutTarget`/`startDrag`): a dragged width (`ui.sizes`) is the pane's `flex-basis`; when every pane not collapsed has one (always so for the only one), the last of them also grows to fill (`filler` in `layout`, `1 0 Npx`), so collapsing or closing the others (or the one pane without a dragged width) never leaves them narrow beside empty space, and the width comes back when a pane without one opens (`tests/test_lone_pane_fills.py`). every expanded pane has one after it, the last pane too (`.glast`, which takes the place of the strip's end padding so it adds no width). A handle resizes the pane before it, or the pane after it when the one before is a collapsed strip. Held within `EDGE_ZONE` of the panes area's far edge for `EDGE_WAIT`, a handle keeps growing its pane (at most `EDGE_GROW` px/s, faster nearer the edge, easing in over `EDGE_EASE`) and `#panes` scrolls by as much; whenever the pane comes up to the size that exactly fills the panes area (`fit()`), by hand or growing, it snaps there (`size()`: `armed`/`stuck`; `.gut.snap`, `#snapTag` "Fits the window", a short vibrate) until the pointer moves `SNAP_PULL` past or, at the edge, for `SNAP_HOLD`; `SNAP_REARM` below it makes it ready again, so the handle stays under the pointer (`startDrag`; Columns and Rows; `tests/test_pane_edge_grow.py`). ✕ (`closeThread`) closes only that pane; open branches under it stay, and the toast's "Close them too" closes them. Main and the document close too, as long as another pane stays open; a closed one stays closed (`setConv` only opens main when nothing is open, `openThread` doesn't reopen main or the document as a parent) until its row in the sidebar's Branches (`data-map=main`, `data-mapdoc`) brings it back. `tests/test_close_main_doc.py`. `tests/test_pane_close_resize.py`.
- **Branch counts** in pane headers are `descendants(tid)` (via `kidsOf`, so hidden ones and, for main in a document conversation, the document's branches are left out); the document's header counts its branches and theirs. One branch is never counted in two headers. `tests/test_branch_counts.py`. The count is a button (`brCount`, `data-brlist`) opening a popover (`.brpop`, `toggleBrList`/`fillBrList`) with that pane's subtree built by `mapNode(tid,{lite:true})`, the same function as the sidebar's tree (no fold, no row buttons); `renderMap` refreshes it, and it follows the header's new button when the header is redrawn. `tests/test_branch_list.py`. The document's list starts with the main thread (just its row: the conversation's other head, so main opens from the document even when its pane is closed; its count is a button even at 0); `tests/test_doc_opens_main.py`.
- **Reply badges** (`markReplies`, `.rbadge`): a thread you can't see (`seenNow`: in Columns/Rows its pane is open and not a strip; on the canvas its card is open or docked) shows three dots while its reply is written (`streaming`) and **Ready** once it's done out of sight (`unread`, per window, in memory only, cleared by `setConv`), on its strip, its folded canvas card and its sidebar row, until it's seen. `markReplies` runs at the end of `layout`, `renderCanvas` and `renderMap`, and when a reply starts and ends; anything new that shows or hides a thread without those must call it. `tests/test_reply_badge.py`.
- **Wires** that cross other panes are masked faint over them (an SVG `<mask>` per wire with `data-crossing`); keep the mask rects in sync with pane rects if wires change.
- **Tooltips** (`#tipbox`): `title=` becomes `data-tip` on hover. They hide on `pointerdown` as well as `mousedown` (canvas drags `preventDefault` the pointer event, so no `mousedown` comes) and don't show while a button is held. `tests/test_canvas_tip.py`.
- **Top bar:** `fitTop` moves whatever doesn't fit (in `TOP_MOVABLE` order) into the ⋯ menu (`.tmore`), the same elements, not copies. It reruns on resize and on changes inside the bar. New top-bar controls go in `TOP_MOVABLE` and `MENU_ORDER`. `tests/test_topbar.py`.
- **Class names:** generic names clash with top-bar styles (`.sel` did). Prefix new canvas classes.
- **Keyboard shortcuts** are one list, `KEYS` (sections of `[keys, what, codes]`; `Mod` is ⌘ or Ctrl), shown by `openKeys` in `#keysPanel`: no backdrop, no focus taken, so keys still work and light their row (`codes` are `KeyboardEvent.code`s with `Mod+`/`Alt+`/`Shift+`). `?` toggles it outside text fields; it's in `closeTopmost`. An iPad (`IS_IPAD`: it says it's a Mac but has touch) shows Zen as ⌃. since iPadOS takes ⌘.; Ctrl works for every `Mod` key. How it works links to it instead of listing keys. README.md's table must list every key in `KEYS` (`tests/test_keys_panel.py`).
- **The tab's dot**: a reply that ends while `document.hidden` sets `tabReady`, and `tabName` prefixes `● ` until the tab is visible again. `tests/test_finish_touches.py`, which also covers the end-of-review summary (`reviewDone`, from `KS.tally`) and the first screen's steps (`emptyState`, only while nothing else is saved).
- **Activity** (`#actBtn` → `openActivity`, `#activity`, its own page over everything, z-index under the flashcards modal; in `closeTopmost`): computed when opened from `io.store.list()` (the open conversation from memory) and `CARDS`, never stored: days from user messages' `ts`, threads' `created` (branches, not `alt`), cards' `reviews[].at`. `recallAt` is FSRS's retrievability; the over-time line replays each kept card's reviews through `fsrsNext`. `tests/test_activity.py`.
