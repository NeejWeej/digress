# Data model, threads, sync, windows

Part of the notes for coding agents; [AGENTS.md](../AGENTS.md) has the overview and the index.

`conv = {id, title, created, updated, rev, threads, msgs, order, ui, nextColor, doc?, pinned?, folder?, archived?, trashed?, views?, llm?}`; `folder`: the name of the sidebar folder it's in (one, no nesting; `''` or missing when none; a folder exists while something is in it; renaming or removing one rewrites every conversation in it, `refileFolder`; personal, so export strips it; a folder's prompt for new chats lives in the store's `prompts/custom` as `folders:{name:text}`, `folderPrompt`: `newChatIn` copies it into the new conversation's `system`, nothing links them afterwards, and moving one in asks first, `offerFolderPrompt`, keeping its own by default; `tests/test_folder_prompts.py`); `trashed` (ms; 0 or missing when not) puts it in the sidebar's Trash (`trashConv`, `restoreConv`); the server deletes it `TRASH_DAYS` (7) after (`purgeTrash`, at startup and hourly; the demo on load), with its layout, search index and any file nothing else uses; search and startup leave trashed ones out; `dropCards` (asked once, when it's trashed, only if it has cards: `trashConv`'s dialog, `cardsChoice`) holds its cards out of review (`cardHeld`, in `inScope`) and has Delete for good and `purgeTrash` delete them; Restore clears it; `srcNote` tells a card in review that its source is in the trash or gone (`cardSource`; `convInfo`, not search's `convMeta`); `tests/test_trash.py`, `tests/test_trash_cards.py`; `llm = [model, effort]` is the model main keeps (the actual model id, never `auto`; without it, the latest reply's model); a branch keeps its own in `threads[tid].llm`, else uses its parent's (`threadLlm`, up to main). The picker shows and edits the thread you're in (`pickerTid`: `curPane()`, on the canvas the selected card; `markCur` and `applyStack` call `syncPicker`); `applyConvLlm(tid)` sets it, `stickLlm(tid)` saves it on a picker change or (if the thread has none) on its first question, in `generate`. A model not offered here falls back to `closestModel` (same kind by `modelTier`, else family) without overwriting it (`llmMissing`/`llmSub`); card drafts and fixes use `modelFor(tid)`; `tests/test_conv_model.py`, `tests/test_branch_model.py`; the picker you see is `#mPick` and its menu (`fillModelMenu`: Default, then foldable groups by family, `FAMILIES`/`famOf`, the current one's open, like Appearance; in a group the newest of each kind by `modelTier`/`modelVer` shows and earlier versions fold under `.molder` Older, open when the current model is one of them), over the hidden `#mSel`, which stays the source of truth (picking sets it and fires `change`; `syncPick` keeps the button's label; a test can list models with `window.fakeModels`); `tests/test_model_menu.py`; `doc.mark` is the reading mark (`['p', page, y]` in a PDF, `['o', offset]` in text, an array so a merge takes one side's whole); `ui` isn't saved with it (per window, `api/layout`); `views = {vid:{name, cv, cam, at}}` are the saved canvas views; `doc = {kind, name, assetId?, text?, source?}` (`source`: the link it was opened from)
- Titles: the first question in `main` names the conversation (and a branch's first question names it) unless `titleKept` (a branch gets it when renamed). When the thread's first reply ends, `nameAfterReply` asks a fast model (`titleModel`: Haiku or Terra, the family the conversation's replies use; `PROMPTS.title`) for a short title, only if the title is still the question and that question isn't already short and clear (`goodAsTitle`); it checks again before applying, so a rename meanwhile wins. The fake page server and the demo answer title calls with nothing (a test opts in with `window.fakeTitles`); `tests/test_auto_title.py`. Before that: the first question in `main` names the conversation unless `titleKept` (typed in the new-from-document dialog, renamed, or taken from the PDF's own title). A PDF conversation without a typed title starts with `autoTitle` (the file name); once pdf.js reads the metadata, `applyPdfTitle` swaps in `info.Title` / `dc:title` if `pdfTitleOk` finds it real and the title is still `autoTitle`, then drops `autoTitle`.
- User messages can carry `images: [{asset|data, type, w, h}]` (pasted screenshots, stored via `io.files`, inline as a data URL where there's no file storage).
- A snip or whole-page branch from a PDF has `anchorRegion: {x,y,w,h}` (fractions of page `anchorPage`; 0,0,1,1 = the whole page) and `regionText` (the PDF's words inside it); its `anchorText` is just a label. The image isn't stored: it's redrawn from the PDF when needed. An image in a text document (a Markdown image or an article's loaded figure; `docImages` wraps each in a `.dimg` with an ask button, markers and boxes, no text) works the same way: the branch has `anchorImg: {key, n, x,y,w,h}` (`key` the image's URL, or `data:<length>.<hash>` for a data: URL; `n` which of the images with that key; the box as fractions of the image) and no `anchorRegion`; the picture is cropped again when needed (`cropRef`, `renderCrop`) from the copy in `conv.doc.images[key]`, made on first use by `docImageRec` (a remote one through the server, `loadArticleImage`). Snip (`startSnip`) handles `.dpage` and `.docbody`: in a text document, a box inside one `.dimg` is that crop (`anchorImg`); any other box is a picture of that part (`shotDocRegion`: the blocks it touches copied into an invisible on-screen frame, since off screen it draws blank, their images swapped for the kept copies, then `html-to-image`, a library loaded like the others; fonts embedded once per font setting, `docFontCss`), kept as a file on the branch (`anchorShot`, an image record: it can't be redrawn, as the text re-wraps) with `regionText` and `anchorRange` (`docBoxText`: the words inside the box, marked in the document like a highlight) or, with no text, `anchorAt` (the image it touched). Export and import carry `anchorShot` (`imageRecs`). The pointer gives screen pixels but a text pane is zoomed (`--pz`, CSS `zoom` on `.docwrap`) and a docked document sits in a zoomed, scaled card, so the box and the picture's frame convert with `screenScale` (measured along the longer side, as `offsetWidth`/`offsetHeight` are rounded); without it the box was drawn off by the zoom, off screen far down a document on a phone. `tests/test_doc_image_snip.py`, `tests/test_doc_snip_anywhere.py`.

- `threads[tid] = {id, parent, anchorMsg, anchorText, anchorRange:{s,e}, anchorPage, anchorEnd?, title, colorIdx, resolved?, pinned?, hidden?, alt?}`. `main` is the root. `anchorEnd: {page, e, s?}`: a PDF passage selected across a page break (`checkSelection`'s `across`; its text and offsets from `crossPageText`, which keeps only text-layer pieces placed where the selection is: the text layer's order isn't the reading order, and a box printed at the top of the first page and its footer once came along in the middle of the quote; see documents.md); `anchorRange` then runs to the end of the passage on `anchorPage` (no longer the page's end), the later pages are highlighted up to `e` on the last, from `s` on it when a running header comes first (`applyDocAnchorsPdf`, which marks them `data-cont` so `refreshDocAnchors` redraws them), and the marker stays where it starts. `tests/test_pdf_cross_page.py`. `alt`: another version of a question (Redo/Edit when the reply can't be replaced): it starts after `anchorMsg` (or `'START'`, before the parent's first message) and its first message gets no side-question prefix. `hidden`: left out of the tree, canvas and reply chips (with what's under it) unless `ui.showHidden`.
- Assistant replies keep `model` and `effort`, `usage` (`{ctx, cached, out, rounds, window?, cacheTtl?, cacheAt?}`: the provider's token counts; `ctx` is the last request's whole input, i.e. how full the context was when the reply ended, `window` the model's context window when the provider says it, `cacheTtl`/`cacheAt` the known ephemeral cache window in seconds and UTC epoch ms for Anthropic/Claude; shown as "52k / 1M context · 75% cached" under the reply, `ctxLabel`), and `docSeen` (`{of, all}` when the whole document went, `{of, tools, pages}` when it started from part of it, `{n, of, pages}` without tools); `reads` is what it read with the document tools. While pending, `live` (steps) and `t0` drive the activity view; they aren't kept (nor `pending`, `ver`, `toolNow`: `LOCAL_MSG`). `run` (saved) is the server run writing it; `runFrom` how much of `content` came before (Continue); `cut` marks one that stopped before finishing (offers Continue).
- `msgs[mid] = {role: user|assistant|note, thread, text, ...}`; assistant replies made with web on also keep `web`, `searches` and `sources`; `order[tid]` lists a thread's message ids. Notes are takeaways carried back from a branch (`fromThread`).
- `ui`: open/collapsed panes (a device with no layout of its own takes the latest other one, its own device's windows first; from another device through `otherScreen`, which drops `sizes`, `pz`, the canvas's `dock`, `pre` and `cz`, sized for that screen), layout (`cols` | `rows`), view (`panes` | `canvas`), per-pane zoom `pz[tid]` (a factor; the PDF pane re-renders at it, where 1 = fit width), canvas state `ui.cv` (positions, sizes, z order, per-card zoom `cz`, docked cards `dock`), `ui.cvView` (the view last loaded) and `ui.cvOwn` (this device's canvas from before it loaded one).
- **Messages are a tree; threads are a labeling of it.** What a message saw is fixed by its path (`ThreadOps.walk`). Anything that rearranges threads must go through `ThreadOps` (`split`, `join`, `swap`; they refuse without changing anything when they can't apply) and keep `tests/test_threads.py` passing. Redo and Edit never replace an answer (`redoKeep`/`editKeep`): with one there, `newVersion` asks again in an `alt` thread starting just before the question, the same anywhere in a thread, the last question included; only a reply that failed or never came is redone in place. "Use this version" (`useVersion`; in the pane's origin line and in a canvas card's `.cq` line, `.cqv`, which for an `alt` card says "Another version of a question in …" instead of "The whole reply") is `ThreadOps.swap`, and its toast offers **Delete the old version** (`confirmDeleteBranch` on what is now the old version). `redoBlock`/`editBlock` still decide what Retry and Continue may change in place (`retryBlock`). Retry (an errored reply) and Continue (a cut one) change a reply in place too, so they follow the same rule (`retryBlock`): Retry asks as another version and Continue isn't offered (this mixed conversations up once). Anything new that rewrites a reply must check it too. **Move what follows into a branch** (the reply's ⋯, `.mfoot [data-act=rmore]` → `openReplyMenu`, `#replyMenu`, in `closeTopmost`; shown when `replyMenuItems` has something: a finished reply with messages after it in its thread) is `ThreadOps.split` just after the reply (`moveRestOut`, which opens it beside, `showVersion`): the rest becomes an `alt` from that reply, so each moved message's context is unchanged. While the thread still ends at the reply, `branchChips` shows it there (`movedOn`; `msgEl`'s cache key includes both); deleting it from that chip is the rewind. Undo is `ThreadOps.join`. A version whose parent ends right where it starts (`joinable`: moved out, or main started over) offers **Move back** (`moveBack`, `ThreadOps.join`, Undo splits it out again as the same thread; a joined version's pane goes, `dropJoined`, since `join` only drops it from `ui`) in place of Use this version, and `useVersion` does the same for it, since swapping in the parent's empty side would leave an empty version; `addMsg` redraws such versions when the parent goes on, so their button turns into Use this version. A version's first card, header line and canvas line say which message it starts after (`altLine`, `versionAfter`). `tests/test_reply_rest_and_images.py`. **Start over** (`startMainOver`, document conversations) is `ThreadOps.split` of main before its first message: main empties and its messages become an `alt` version from `START`; Undo is `ThreadOps.join`. **New conversation from this document** (`newFromDoc`) copies `doc` (not `mark`) and shares its `assetId`. `tests/test_redo.py`, `tests/test_versions.py`, `tests/test_start_over.py`.
- **Several devices: saving is versioned and merged.** `flush` saves only the content (`contentOf`: no `ui`, no `LOCAL_MSG` fields) and only when it changed (`sync.sent`), from version `sync.rev`; a 409 goes through `mergeRemote` → `ThreadOps.merge(base, mine, theirs)` → `applyContent` (keeps the objects of replies being written here) → saved again. If merge throws `{conflict}`, `keepCopy` saves this page's version as "… (from this device)"; `{later}` (a reply here is mid-way and would need new ids) waits for it to finish. `catchUp` runs when the tab comes back (visibilitychange, focus, online). `ui` goes to `saveLayout` separately. A save that fails (a dropped connection) keeps `dirty` and retries (`retrySave`: 2 s, doubling to 30 s; `saveSoon` at once on `online`, the tab shown or hidden, `pagehide`); while `saveFailed`, leaving the conversation asks (`leaveOk`, before `openConv`, New, from a document) and `beforeunload` warns. `tests/test_save_retry.py` (the fake server's `window.fakeOffline`). Anything new in a conversation must survive `merge` (add it to `tests/merge_prop.mjs` if it has rules beyond "one side changed it"); per-page state on a message goes in `LOCAL_MSG`. `tests/test_sync_devices.py` drives two browsers against the real server; `tests/test_sync_replies.py` covers replies that outlive their page (another conversation, a reload, a dropped connection, cut off + Continue).
- **Several windows on one machine** share the device ID (`DEVICE`, localStorage). Each window also takes a number (`WINDOW`: the lowest Web Lock `digress:window:n` no other window holds, kept in sessionStorage so a reload keeps it) and saves its layout under `layoutKey()`, so a canvas in one window and columns in another don't overwrite each other. Every save, rename or delete of a conversation is announced on the `BroadcastChannel('digress')` (`toldWindows` wraps `io.store`); the window showing it runs `catchUp(true)` (a window on another monitor stays visible and never gets focus, so it wouldn't otherwise). The address names the open conversation, `#c=ID` (`showInUrl`, replaceState, only once saved; startup reads it in `maybeOpenLatest` before writing it); ⌘/Ctrl- or middle-click in the sidebar opens a conversation in a new window. The tab is named after the open conversation (`tabName`: "<title> · Digress", from `renderTitle` and `applyContent`); it was once "Digress 2 · Canvas" to keep titles out of browser history, but that said nothing useful. `tests/test_windows.py`.
- **Where a takeaway ends** (`takeawayCut`): a takeaway note records `upTo`, the last message of its branch it saw (older ones are worked out from the messages' `ts`). Once the branch goes on past it, a divider (`.tkcut`, `takeawayCuts`, `tkcutEl`) sits after that message in the pane and the canvas card; it goes to the note (`goToTakeaway`), and the branch's name in the note's header goes to the cutoff (`goToTakeawaySource`). The divider sits between messages, never inside one, so anchors are unaffected. `tests/test_takeaway_cut.py`.
- **An empty new conversation** (`isBlank`, the one rule for it, `flush` included: a conversation with only its own system prompt or skills is kept; no document, nothing in main, no branches) is never saved (`flush` skips it), so Delete or ✕ on its only pane runs `discardBlank`: drop it (delete it if it somehow was saved) and open the latest other one (`openNextAfter`, also what deleting the open conversation for good does). `tests/test_blank_conv.py`.
- **Export and import** (`openExport` from the sidebar row's `data-expconv`; `digressFile`, `exportDigress`, `convMarkdown`, `exportAnki`, `importDigress`): a `.digress` file is gzipped JSON (`CompressionStream`) `{digress:1, exported, conversations:[contentOf], cards, files:{assetId:{type,data}}}`, built and read in the browser (the only requests are GETs of its own files). Left out: `ui`, `rev`, pins, archive/trash, `doc.mark`, `conv.cards`, card schedules; the document unless ticked (then `doc.left`, and the missing-document message asks for the reader's copy, `reattachDoc` clears it). Import (`#docFile` accepts `.digress`; a drop anywhere outside `#docDrop`) checks each conversation (`fresh`: shapes and `ThreadOps.check`), gives it a new id, stores images and the document again (`storeImages`, `storeDocFile`) and saves with `io.store.save(id, c, 0)`; cards come in as `inbox`. Anything new on a conversation that is personal or per device belongs in the strip lists there. The demo uses the same code (its `api/*` is in the page). `tests/test_export_import.py`, `tests/test_demo.py`.
